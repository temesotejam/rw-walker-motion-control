# v14 エネルギーによる歩行入力の決定

2026-11-13。専用環境 `atoms3cam-foot-support-energy`、build ID `foot-support-energy-v14`、通常・足前倒し・救済の制御branchは19。v13を比較基準として保持する。

## 変更する動作

v13の±8度では角度ピーク/角速度からmsを増減するbranch15と、足量による追加msのbranch18がエネルギー逆算より優先されていた。v14では実際のパルス幅をJ単位の不足量と到達仕事予測から選ぶ。実装は `walking_energy_policy.h` と `walking_energy_runner.inc`。

姿勢/角速度は既存の6状態MEKFを使用する。目標は4.5度から8度へ既存の交互ピーク観測で段階的に上げるが、これは目標エネルギーの変更であり、入力msを直接増やす処理ではない。MPCは使用しない。

## エネルギーと入力幅

すべてJ単位、角速度はrad/sへ換算する。名目円弧形状の同じ位置エネルギー関数Uを現在角度・観測ピーク・目標に使用する。CG移動を推定する旧補正との混用はしない。

```
E_available = U(theta) + b_side * omega^2 + a_side * min(1,rate_dps/20)^2
E_peak_in  = U(incoming_peak)
E_peak_same = U(previous_peak_on_target_side)
E_mean = (E_peak_in + E_peak_same)/2
E_difference = (E_peak_in - E_peak_same)/2
common = clamp(0.25*(U(target)-E_mean), +/-0.125*U(target))
redistribution = clamp(0.125*E_difference, +/-0.125*U(target))
request = max(0, U(target) + common + redistribution - E_available)
width = argmin_integer_0_to_cap abs(W(Q(width))-request)
```

ピークの組が無ければcommon/redistributionは0。入力に先立つ直近ピークは1500ms以内を要求し、同側の過去ピークは3000ms以内だけ使用する。起動時の同側ピーク欠測は許す。左右ピークは別時刻の観測であり、二つの物理エネルギー槽を同時に測った値ではない。これらの補正を後述の「エネルギー的中立点」の推定とも呼ばない。

`b*omega^2` は実測coastの次ピークUへ回帰した有効到達エネルギー指標で、同定された機体慣性による瞬時運動エネルギーではない。正の切片も静止時の運動エネルギーではなく、20度/s未満の減衰補間は暫定である。

幅からQは電流飽和・立ち上がりモデルと符号付き初期電流で求める。1200mAは指令であり実電流ではない。Wは既存の `c1*omega*q+c2*q^2` の到達増分モデルを移植した暫定値。未同定の足接触損失やモータ効率を確定値としない。負方向の受動モデルと仕事モデルの角速度支持範囲は重ならず、負方向は常にどちらかの外挿を含む。

足の前振れ量・局所戻り/初回反転・履歴予測は、既存の画像遅延と鮮度を考慮して入力時機を選ぶ。足量から固定msを加えず、惰行を固定15msへ変更しない。現在は足形状に基づく追加障害Jも0。画像の脚角から必要仕事が同定済みとは扱わない。

## 実行経路と制限

通常と足前倒しは最大80ms、足以外の前倒しと失速救済は最大15ms。既存の時間/電圧/車輪/画像/IMU保護はさらに減幅・不採用にできる。減幅後のQ・W・到達予測・未達Jを再計算する。無効値、古いピーク、輸送失敗で旧ms制御へ戻らない。

起動の300mA/100msキックは従来の固定入力を明示した例外として維持し、それ以降をエネルギー方策に通す。惰行は新しい入力を出さない意味であり、残留電流/ホイール保存エネルギーが0とは主張しない。残留の診断Qを既存の到達モデルへ重ねて二重計上しない。

旧幅学習・足振幅によるms試験・coast上書き・幅の速度テーパは実出力の選択に使わない。旧観測器がpendingになるだけで新足前倒しを抑止する問題も避ける。tilt_priorityには段階目標と経過時間の保護だけを担わせる。

## 機構上の中立とエネルギー的な中立

ユーザーの補足に従い、機構上の角度基準theta=0と、足姿勢に応じた位置エネルギーの谷theta_Eを区別する。支持脚の切替角theta_Sも別の量である。一般には `U(theta,alpha_L,alpha_R)` の形状を求めて、その谷と途中の山を調べる必要がある。

このv14の実制御はまだ名目円弧Uを使う。左右ピーク補正は移動する谷を同定するものではない。CAD形状から求める凍結足姿勢の高さ/ポテンシャルの診断は別資料に記す。谷の角度だけをUへ平行移動すると形状変化を落とし、足角ごとのゼロ再設定も足の運動による仕事を消してしまう。現在のcoast回帰へCAD補正を片側だけ足すと足運動の効果を二重計上し得る。質量/CG・足角の基準・将来足姿勢を整合させてから動く谷を実制御へ反映する。

診断の式・条件付き数値例・粗いGLBメッシュが作る偽の谷・必要な校正は `ENERGY_NEUTRAL_V14.md`。例えば重心高さ120mm等を仮定した左CAD角0/右4度では、谷はCAD機体角約-6.26度へ移る。これは実機角度の推定値ではなく、足を固定した接触/集中質量モデルの計算例である。機構ゼロまでの上りを、そのままモータの必要仕事とも扱わない。
