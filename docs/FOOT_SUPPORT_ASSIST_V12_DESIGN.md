# v12：通常幅を保った前置き入力と、中心手前の減速への限定経路

2026-11-13。v11を変更せず、`src/foot_support_assist_v12.h` に別のportable selectorを実装した。機体の揺れと支持移動・歩行は区別する。この文書の上限値は試験上限であり、必要仕事量や機体の安定性を証明した値ではない。

## v11ログで確認した限界

run 141282685では、新しい入力は7.429・9.034・10.652秒の3回、正側15 msのcoast補助として実行された。一方、27.622秒の負ピーク後は中心を通れず、27.958秒の従来15 ms救済も通過を成立させなかった。

この終盤では右足が約5.76度まで前に出て戻っていたが、履歴予測のconfidenceが低く、v11は新しい入力を許可しなかった。また、通常の提案幅約70 msはv11の移動上限60 msを超え、さらに向心速度が落ちると角度/速度で見積もる中心到達時間が250 msを超える。後者は遠くにいるだけでなく、中心手前で戻りが弱くなった場合にも起こる。

これらを受け、v12は局所観測での足のReturning確認を利用できるようにし、通常幅の移動上限と、250 msを超える場面の限定条件を別々に変更する。局所足推定器とrunner統合は別のファイルが担当する。

## 変更1：通常提案幅を縮めず80 msまで前へ移す

通常driveの移動上限を60 msから80 msへ変更する。例えば、その判断時点での通常提案が70 msなら70 msをそのまま候補とし、60 msや15 msへ切り詰めない。80 msを超える通常提案は不採用とし、80 msへ丸めない。

これは既存通常出力のハード上限150 ms以下の試験範囲だが、それだけで早い時刻に出す安全性が保証されるわけではない。通常と同じ電流設定・車輪・タイミング・送信状態のガードを通し、ガード後に幅が短くなれば早期移動をやめて通常ZEROの機会を残す。将来のZERO時点で同じ幅が選ばれると保証したものではなく、あくまで現在の通常提案幅を基準にする。

## 変更2：見積もった中心到達時間が大きい減速場面

v11と同じ `estimated_zero_ms = 1000 * body_distance / inward_speed` を用いる。これは一定速度の見積もりで、実際の支持切り替え時刻を予測した真値ではない。

250 ms以下ならv11と同じ時間条件を使う。250 ms超は一律不採用とせず、次の全条件を満たす場合だけ `stall_route=true` の別経路を許可する。

- 同じrun・ピークにおける新鮮な向心運動で、現在の速度が6〜45度/秒。停止後、すでに折り返した外向き、中心を通過済みの場合は不採用。
- 機体の中心までの距離が0.8度以上、かつ足姿勢に応じた閾値以下。閾値はv11と同じ `1 + 1.2 * forward + 0.3 * asymmetry` を1.5〜5度へ制限する。
- 最近の向心速度が4度/秒以上落ち、それが10 ms以上持続したことを、別の因果的な検出器が確認している。単に速度が低いこと、古い最大速度から下がったこと、単発のgyroスパイクは根拠にしない。
- `anticipated_shape_need=true`。これは不確実性を差し引いた前振れ量・左右差が各1度以上、主要な足がReturning、入射側の機体ピーク8.5度以下という形状条件をrunnerが確認したもの。大きい・小さい機体ピークを歩行成功の証拠にはしない。
- `local_returning_confirmed=true`。主要な足が戻っていることを、最近の局所的な有効観測が因果的に裏付けている。履歴の予測だけ、または単一の減少サンプルでは不足。
- 見積もった中心到達時間が500 ms以下。

つまり、`inward_decelerating && anticipated_shape_need && local_returning_confirmed` と左右差の数値条件が必要であり、どれか一つを満たしただけで250 ms上限を外さない。500 msも独立した試験上限で、任意に遅い遠方の動きを失速として許可しないために設けた。既存の速度下限6度/秒は緩和していない。

パルス幅に対する短い時間余裕の拒否は維持する。通常経路も失速経路も、見積もり時間が `requested_width_ms + 20 ms` 以上でなければ不採用。この20 msは一定速度の仮定の下のスクリーニングであり、足裏の障害位置や実際の到達期限を保証しない。減速中にこの下限を緩める必要はなく、250 msを超える側だけを追加の証拠で扱う。

## 維持する条件

run ID、ピークID、時刻の整合、画像年齢160 ms以内、足推定の有効性、左右の不確実性各0.75度以下、前振れ代理量1度以上、通常drive/coastの整合性はv11と同じ。`pose_confident` は履歴一致度だけでなく新しい局所推定器の品質判定から得ることもできるが、基準を満たしている責任はcallerにある。confidenceや不確実性を物理真値の確率・誤差境界とは扱わない。

通常coastは15 msのまま。通常driveを15 msに縮める経路はない。通常coast単独では補助を許可せず、v11同様、実減速または先回りの形状条件を必要とする。250 ms超のcoast補助は上記の追加条件も全て必要で、最大15 msを維持する。

selectorは無状態で、モータを書き込まない。runner側の一ピーク一回、正常ZERO優先、緊急停止、パルス中の除外、ガード後の幅一致、送信なしの状態復元、曖昧な書き込み時の停止を引き続き使用する。減速・局所Returningの証拠もrun/ピークの更新、欠測、古いIMU、外向き・中心通過で失効させる。

## APIと比較検証

`Input` はv11のInputを継承し、`local_returning_confirmed` と `prediction_source` を追加する。`PredictionSource` はUnknown / History / Local。`Decision` はv11の既存フィールド名を維持し、`stall_route`、`mode`、`prediction_source` を追加する。通常幅の移動、coast補助、およびそれぞれの失速経路を監査上で区別できる。

理由コード0〜16はv11と同じ意味と番号を維持する。17は `StallNeedsEvidence`、18は `StallTooEarly`。失速用の証拠不足と500 ms超を分ける。

`decide(input, Limits{})` のデフォルトは通常幅80 ms・失速経路有効。Limitsはコンパイルされた80 ms上限を広げられず、比較のための削減だけに使える。

- `Limits{60, false}`：局所足推定だけを変え、出力方針はv11相当。
- `Limits{80, false}`：通常幅80 msへの変更まで。
- `Limits{80, true}`：v12の全条件。

`tools/test_foot_support_assist_v12.py` は70/80/81 msの境界、通常幅の保持、250/500 msの扱い、実減速・形状・局所Returningの個別欠如、停止・外向き、coast15 ms、画像年齢等を確認する。さらに60 ms・失速経路無効の条件で、足角度・機体角・速度・幅・drive/coast・証拠を組み合わせた全56,448ケースについて、v11と選択結果・幅・理由コードが一致することを検証する。

旧ログの因果再生は候補が現れる時刻や不採用理由を比較するために使う。新しい入力後の実際の機体・足の運動は再現していないため、実機での歩行改善や安定性を確認したとは扱わない。最終評価は映像とログで支持移動、左右交互の足運び、前進の連続を確認する。

## runner統合で確定した意味

通常幅は、生のproposalではなく、同じ車輪ガードのコピーと新鮮な車輪観測で確認した「保護後の通常幅」をselectorへ渡す。例えば今回の停止窓は生70 msから車輪保護で68 msになる。backendは生70 msへ実ガードを一度通し、要求68 msと一致する場合だけ出す。ガードを迂回せず、previewで実ガード履歴を消費せず、速度taperも二重に適用しない。実ガードが別の幅になれば送信しない。

履歴予測が既存の品質条件を満たす時は優先し、その場合は通常の250 ms上限を維持する。今回のstall経路は、採用sourceがLocalの時だけ使う。反復モデルの一致度を人工的に増やさず、局所3点のReturningと内部余裕を別の根拠として扱う。

局所観測の有効窓が短いため、v12だけfoot snapshotの確認間隔を25 msから10 msへ変更する。画像認識と局所モデル作成はCore0、Core1はコピーと小さい照会に留める。10 msの実時間期限を保証したものではなく、次のログでreadyから初回制御観測までの遅れを確認する。

監査は生通常幅・preview保護後幅・要求幅・実ガード後幅、予測source、候補時mode・最終再判定mode、stall経路を分ける。v12はbranch17、未同定モデル名foot_support_local_unmodeled_v12で識別し、arrival modelはnull。v11のbranch16と混同しない。
