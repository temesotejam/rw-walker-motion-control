# 足認識 v27：段階コピーの重複削減

2026-11-17。ユーザー依頼「引き続きカメラ認識の高速化」に対応する比較候補。実機への書込み・操作は行わず、ユーザー用のブラウザ書込み版を作る。

## 比較基準と狙い

基準は `walking-foot-native-stream-v26-webfix1` の試行117625571。ドライバ画像記録時刻から制御初回受取まで中央値27.771 ms、p95 32.694 ms、最大40.059 ms。画像更新は27.987 Hz、最長間隔366.653 ms。詳細は [試行レポート](TRIAL_117625571.md)。物理露光時刻を校正した遅延ではない。

目標20 msに向け、段階画像処理のコピー負荷を減らす。新候補の遅延・更新頻度・欠落改善は実機で未測定。センサー読出し自体の時間は今回短縮していないため、この変更だけで20 msへ届く保証はない。

## 変更

- 下側マーカーは論理行174/190/206/222まで段階的に準備する。従来は各段階でそれまでの行も再コピーしていた。v27は同じフレーム時刻の続きだけをコピーする。HAL→所有権付きメールボックス、メールボックス→認識用内部RAMの双方に適用。
- 完全な4段階を各々処理するテストでは、下側1経路のコピー量が40,320→12,800 bytes（68.25%減）。2経路合計では80,640→25,600 bytes。上側・通常フォールバック・プレビューなどを含む全コピー量や実行時間の削減率ではない。段階がまとめられる場合や共有領域を再利用した場合、実際の削減量は変わる。
- 足観測が画像を取得している間だけ、HALの準備用コピーを有効にする。処理中・待機中の使われない準備を抑える。すでに所有されている領域を強制破棄せず、時刻一致で採用する。
- 新しいフレーム、古い時刻、逆行する行範囲、欠損行を区別する。上側画像や通常処理が共有RAMを上書きする前に下側キャッシュを無効化する。
- 完全なフレームのサイズ・形式・時刻が確認できるまで、準備した特徴量を追跡状態へ反映しない。不一致時は従来の認識へ戻る。

センサーHB96・クロック・320×236画像・校正座標・探索範囲・タスク配置・33,333 us周期・エネルギー制御v19は維持。ログ取得webfix1を継承し、旧専用インストーラーも保持する。
