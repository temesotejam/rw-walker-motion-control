# 足認識の遅延集計・26 ms周期比較（2026-11-17）

## ユーザー提供レポートの反映

提供ZIP「カメラ認識性能調査レポート」（SHA256 `e9298b8615bddb9ae31336ed11c36e0c374bbed86ae5b7d60cc3c3793ac714f1`）はv29時点の整理。原文MDはローカル `analysis/2026-11-17-camera-histogram/reference_report.md` に保持し、Gitには含めない。

実装と照合した重要点は、センサー単体の約49 Hz、観測ワーカー設定上限30 Hz、画像1枚の受取り遅延を区別すること。26 ms周期案は更新頻度を上げる案であり、20 ms遅延を保証するものではない。受信待ち・不完全画像・キューあふれの計測はv30を継承し、今回は実際の初回制御受取りを本体内で集計した。水平待ち短縮とワーカー周期短縮は別の版で比較する。

## 実装

- v32 `atoms3cam-foot-histogram` / `walking-foot-histogram-v32`: v30のHB96/33.333 msを維持。`FootObserver::recordControlObservation` で同じrun/sequenceの初回受取りだけを数える。再受取り・別画像・別runは重複計数しない。256個・250 us幅のヒストグラム、合計時間、検出数、無効時刻数を既存mutex下で更新する。スナップショット後のJSON生成はmutex外。
- GET `/camera/latency.json`: 起動ID、停止/コマンド状態、受取り集計、受信欠落カウンタ、通常status/preview要求回数を返す。既存PSRAM出力バッファを再利用し、割当・出力失敗を検出する。測定の開始・終了だけ読み、計測中のHTTP負荷を避けられる。制御コマンドやカウンタリセットはない。
- v33 `atoms3cam-foot-hblank80` / `walking-foot-hblank80-v33`: v32からHBだけ80へ変更。実機で白化・検出不能を確認し不採用。センサーをさらに速める根拠として扱わない。
- v34 `atoms3cam-foot-worker26` / `walking-foot-worker26-v34`: HB96と全認識範囲を維持し、ワーカー周期だけ26 msへ変更。設定上限38.4615 Hzを状態/メタデータに明示する。予測器の25 ms下限・制御のエネルギーv19・モータ入力は変更しない。

開始LED同期5 s＋測定30 s＋終了同期5 sを記録するため、v34では足ログを1280件から1600件へ増やした。26 ms周期の40 s分は最大約1539件であり、1600件に余裕がある。メタデータ上限1280 KiB・予約1408 KiBへ拡張し、足ログを間引いて旧容量へ押し込む方式にはしない。従来の各ビルド設定は変更しない。

## 計測の意味

ヒストグラムは**制御側が初めて受け取った観測**の分布。全センサー画像でも、校正済みの光学露光時刻からの遅延でもない。最後のビンは63.750 ms以上すべてを含む。表の分位点は `[下端,上端)` の0.25 ms区間であり、架空の精密な中央値を作らない。最大値・最大間隔は起動累積なので、区間最大値として流用しない。各カウンタは同じ起動内の差分を使用する。

USBのみでモータ停止、測定開始コマンド0。機体を横置きから立位へ変更した旨の申告があったため、姿勢の異なる区間を単純な性能比較に使わない。Web画面を閉じた後も、status要求差分0・preview差分0を確認して初めて「通信なし」とする。画面を再度開いた区間はそのまま記録し、再測定した。

## 検証

- 実observerの初回受取り処理・ヒストグラム: 重複、別run/sequence、時刻逆転、端のビン、最大整数JSONを検証。
- v34実observer統合: 周期・過負荷待ち・1600件境界・借用画像所有権・不完全画像拒否・プレビュー保持・投影時刻を検証。旧fixtureの70画像は26 msでは2 s未満になるため、シナリオの静止期間を90画像へ延長した。製品のゼロ点確定待ち時間は変えていない。
- 最大容量の実serializer→RWLOG→CSV: v34の足1600、エネルギー192、支持96件を末尾まで保持。1117387 bytesで上限1310720 bytes以内。任意の予測コピーは従来と同じ優先順位で省略し、raw足観測と制御監査を保持する。
- PSRAM容量モデルは非driver余裕605267 bytes。これは実ヒープ測定や歩行後の断片化保証ではない。v34で追加の足配列・予約容量を確保して起動できたことは実機確認する。
- 旧observer10構成、センサー設定の故障注入/HB境界/v33上書き、18インストーラ構成、HALリンク、埋込みWebの整合性を検証。前回判明した旧固定ハッシュテストの不一致は今回の新規回帰として扱わない。
