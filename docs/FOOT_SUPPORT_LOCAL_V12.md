# 足の局所的な戻りを扱う試験版 v12

2026-11-13。build ID `foot-support-local-v12`、環境 `atoms3cam-foot-support-local`。v11と書き込みページを分ける。

## 今回の変更

v11実機141282685では、終盤の右足5.76→5.37→3.96°という有効な戻りの観測が届いても、反復モデルに似た動きがないため補助から外れた。同時に通常proposal70 msが前倒し上限60 msを超え、減速で中心到達時間の一定速度見積もりも250 msを超えた。この3点を一緒に扱う。

1. **局所の足観測を補完に使う。** 履歴予測が従来の品質条件を満たす時は優先する。そうでない時に限り、同じrun・画像の直近3有効点から、主要な前方足の2区間連続の減少を確認する。単一の反転直後や欠測を、確定した戻りとして使わない。
2. **保護後の通常幅を、最大80 msまで前へ移す。** その場の通常提案を縮めて別の弱い入力にしない。車輪保護のコピーで通常幅を確認し、backendで実ガードを通した幅と同じ場合だけ送信する。電流指令を一律に増やす変更ではない。
3. **中心手前の減速を限定的に扱う。** 中心到達見積もりが250 msを超える時は、採用sourceがLocalで、局所Returning・足形状根拠・持続した向心減速が揃う場合だけ別経路を使う。500 ms上限、幅＋20 msの下限、向心速度6°/s以上等は維持する。停止後や外向きの機体に、この経路で入力しない。

局所モデルは、戻り方向に遅い方の局所速度で最大25 ms分・最大0.5°の小さい補正だけを行う。未観測の頂点を越える強い外挿はしない。反復モデルのconfidenceは0のままでも、別の局所証拠を使える構成で、confidenceを水増ししない。内部marginは真値を必ず含む誤差保証ではない。

画像からの結果を早く受け取るため、v12だけCore1のfoot snapshot確認間隔を25 msから10 msへ変更。画像処理・局所モデル作成はCore0のまま。確認間隔は実時間期限の保証ではない。

## 今回止まった場面の再生

実C++ヘッダと同じsource選択関数を使い、過去の観測を到着時刻順に投入して比較した。

| 条件 | 27.921秒の判定 |
|---|---|
| v11の反復予測 | PoseUncertain |
| 局所補完だけ・幅上限60 ms | Width：車輪保護後の通常幅68 ms |
| 局所補完・幅上限80 ms | TooEarly：中心到達見積もり263.5 ms |
| 局所補完・80 ms・限定失速経路 | **68 msの候補成立、車輪保護後幅と一致** |

この状態の生の通常提案は70 ms。直前の車輪観測378.91 rpmと現在1.81 rpmを既存wheel guardへ通すと68 msになり、その68 msを要求する。車輪保護を無視して70 msを出すものではない。

追加の受け取り遅れを0/10/15 msとした時は、27.921/27.927/27.932秒に68 ms候補が残り、旧15 ms救済27.958秒より37/31/26 ms前。25 ms遅れでは候補がない。critical画像の実際の初回制御受け取り時刻は保存64標本に含まれないため、次の実機で確認する。

8ログの比較では、今回141の停止前に加え、旧848の停止場面にも59 msの局所・失速候補が出た。旧279の26.5秒停止直前には候補がなく、全停止の解決とは扱わない。旧199では保護後通常幅53 msを使うことで通常経路の候補が1件増えた。

過去の指令・ピークで通常制御と車輪ガードを更新した、元の軌道上の候補比較である。完全なhardware/current/battery/driver経路や、新しい68 msを出した後の運動は再現していない。候補成立は実機での実行・支持切り替え・連続歩行の成功を意味しない。

局所モデルは全体の点精度を良くするモデルと断定しない。今回の実fallback層32角値でMAE0.570°（保持0.613°、旧直線0.558°）、内部margin内は65.6%。方向の粗い照合でも取り違えは残る。過去3点の証拠と、現在の足方向や接地の保証を分ける。
