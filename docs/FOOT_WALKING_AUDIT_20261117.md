# v37 歩行試行中の足角度・処理経路の確認

2026-11-17。対象は `energy_control_autonomous_run_1_46492793.rwlog` と `energy_control_autonomous_run_2_201405726.rwlog`。ユーザー観察は、1回目「足を前に出しすぎて後ろに転倒」、2回目「胴体が前へ傾きESTOP」。いずれも歩行成功とは扱わない。今回はユーザー指定に従い、歩容調整よりも測定・制御・停止・保存の仕組みが動いているかを確認した。

## 結論

両ログとも `walking-foot-cadence20-v37` / `walking_energy_admission_v19`。動作中にも足画像→認識角度→制御受取り→足姿勢に基づく補助入力→前後姿勢悪化によるESTOP→RWLOG保存までの記録を確認できる。単なるWeb表示の成功ではない。一方、動的な角度精度、連続歩行、転倒を防げる停止時点、厳密な一定周期は未検証または未達。

## 実際に記録された足角度

正は足が前に振れる方向という既確認の符号に沿う。ただしカメラ・胴体に対する相対角であり、地面基準の足姿勢そのものではない。

| 項目 | 1回目 | 2回目 |
|---|---:|---:|
| 左足有効値の範囲 | −0.577〜20.174° | −0.539〜20.380° |
| 右足有効値の範囲 | −0.212〜4.698° | 0.005〜6.789° |
| 左足最大の時刻 | 10.526 s | 23.166 s |
| 最後の画像 左 / 右 | 18.100 / 0.006° | 9.077 / 6.789° |
| 最後の画像時刻 | 10.872 s | 23.696 s |

両方とも左足の大きな前振れが記録され、左右差を測定できている。1回目は10.4〜10.5 sの約0.1 sで左角が約3°から20°へ増加し、その後も18°前後を更新した。2回目は19 s台から左角が大きい状態を継続して追跡し、23 s台にも約20°を記録している。左角20°は、同時点の有効マーカー座標・測定済み校正範囲内から算出されており、範囲外の値を20°に固定した結果ではない。

校正表の区分線形補間と各起動ゼロ座標から左右の角度を独立再計算し、全有効値で差0.0001°未満。これは座標→角度変換と保存の整合確認であって、物理的な角度精度0.0001°を意味しない。校正自体は暫定で、動的な角度精度と上下移動時の投影誤差は未検証。新たな同期動画や外部角度基準は今回提示されていないため、正しいマーカーを常に選べていたかまで断定しない。

2回目の最後は両足角が同時に急増し、胴体前後角も急変している。胴体が傾くとカメラ基準の足角も変化するので、この部分を「左右の足を同時に前へ振った」と読み替えない。

## 予測と実制御への接続

履歴予測Readyは1回目507/524 (96.76%)、2回目1065/1133 (94.00%)。局所予測Readyは503/524 (95.99%)、1041/1133 (91.88%)。`Gap` と `Stale` は両試行0件で、高頻度画像が周期下限により一律拒否される状態ではない。各試行最初にTimestamp1件があり、計測境界の履歴がまだ成立しないフレームを拒否している。

予測器の `Jump` は6件 / 23件。現在の制約は8°超の隣接変化または80°/s超を拒否する。この試行には左足約161°/s、約206°/sの画像上の変化があり、検出が有効でも予測を使えない区間がある。これは予測器の意図した拒否動作を確認したという意味で、実際の速い足運動と誤認識のどちらかは独立基準なしに判定できない。2回目最後の2フレームはJump→Warmupで、角度は測れても予測Readyではなかった。

現在のv19補助入力は最新の生の足角度・有効性・範囲・鮮度とIMUの減速を使う。全ての入力が履歴予測に依存するわけではない。`return_observation_policy::assessFoot` では新鮮な両足有効値の左右差3°以上を `ObservedShape` とする。

- 1回目：エネルギー判断51件、入力実行23件、うち足姿勢を根拠とする補助入力2件（8.258 / 10.693 s）。判断時の足画像年齢34 / 46 ms。
- 2回目：判断86件、入力実行47件、同補助入力8件。判断時の足画像年齢28〜50 ms。
- 全補助入力の `return_evidence=ObservedShape`。最新の既受取り画像との因果順序を確認し、いずれも両足有効の画像と対応する。ただし判断レコードが画像sequenceを直接保存しないため、完全な同一ID証明とは区別する。
- 画像を受け取った時点の約26 msの遅れと、次の判断まで保持した時点の28〜50 msの画像年齢を区別する。
- 全実行レコードで入力開始・終了・実経過時間・完了有効性が整合する。入力指令と実電流応答も時系列にある。指令の±1200 mAに直ちに実電流が到達するという意味ではない。

制御はエネルギーv19のまま。今回のカメラ高速化による角度ピーク幅調整への置換はない。一方、物理的な必要仕事の完全同定やイベントホライズンMPCが完成したという主張もしない。足姿勢を使った補助入力が発生したことと、その入力が歩行を適切に改善したことは別である。

## ESTOP・保存と残る課題

両ログとも末端は `ESTOP` / `fore_aft_outward_divergence`。前後姿勢ガードは開始姿勢に対し1回目+8.531°/+62.911°/s、2回目−11.325°/−87.277°/sを記録し、両方向の悪化で停止した。ユーザーの後方・前方という観察と方向の違いが整合する。停止後の出力指令は0、保存時の実電流は+1 / −1 mA。ガードの条件成立と停止経路を確認できるが、転倒に間に合う安定限界の物理検証ではない。

両ファイルともCRCと長さが一致し、足・エネルギー記録の容量あふれなし。2回目も保存・ダウンロードできたというユーザー報告と一致する。今回の停止を、過去の `Failed to fetch` やログ破損と同一視しない。今回の2件から将来の全通信成功を保証はしない。

機構確認として未解決の点も残す。

1. 動的な角度の真値精度は未確認。校正座標の整合・高い検出率だけでは証明できない。
2. 2回目に約101 msの有効観測空白、急運動時の予測拒否がある。常時一定周期ではない。
3. 制御処理の2.5 ms目安超過は58/4410回、117/9600回。最大4.132 / 4.305 ms。これはホストIMU取得→runner復帰の区間であり、センサー露光→モータ反映の期限ではない。長い停止は見えないが、厳密な期限保証はない。
4. ソフトウェア入力経過時間は指令より最大1 ms長い。2回目に80 ms指令に対し81 msが1件あるため、80 msを物理的な厳密上限とは説明しない。
5. `foot_observation.predictor_min_interval_ms` の診断文字列は25 ms固定のまま。v37の実装定数は15 msであり、Gap0件の実測とも合う。これはメタデータの残存表示不整合として次回修正対象。今回の解析ではソースと実測を優先し、ファームは変更していない。
