# 足姿勢と遅延を考慮する試験版 v11

2026-11-12。build ID `foot-support-assist-v11`、PlatformIO環境 `atoms3cam-foot-support-assist`。v10と書き込みページを分けて保存する。

## 今回変えたこと

足角度は、認識結果が届く約77 ms前のフレームの観測として扱う。Core0で左右3フレームの軌跡に似た過去履歴を探し、既知の後続変化から短時間先の4点を作る。Core1はその4点を使って、実際の制御時刻の足姿勢を軽く照会する。未知の動きや候補不一致は保持・低信頼側へ戻す。

入力判断には現在姿勢 `predict(now,0)` を使う。30 ms先の値は診断用に残すが、30 msを実測済みのモータ応答遅延とは扱わない。最新フレームが無効なら、その無効状態も制御へ伝えて前の予測を失効させる。

新しい入力は、足の前方への量・左右差・前振れと戻りの位相、機体の位置・向心速度に合わせる。CAD絶対原点と前後姿勢は未校正なので、CADの高さ一致角を実測接地角として出力へ使用しない。

## 入力は2通り

1. 通常制御がdriveを提案する時は、その時点の通常幅を早い位置へ移す。上限60 ms。60 msへ丸めたり、後段ガードで幅が短くなったものを早期入力として通したりせず、不採用として通常ZEROの機会を残す。将来ZEROで選ばれるはずの幅と同じであるとは保証しない。
2. 通常制御がcoastを提案する時は、形状の変わった足で支えを移すため、限定条件で15 ms・1200 mAの指令を試す。大きな機体ピークだけで十分な支持切り替えができるとは限らないため、従来のcoast判断をこの条件に限って上書きする。通常出力への15 ms加算ではなく、その半周期で1回の入力である。

coastを上書きできるのは、足の出方等の共通条件に加え、以下のどちらかがある時だけ。

- 同じrun・ピークで、短い履歴から持続した向心減速を確認した。
- 前方量から内部の不確かさ余裕を引いた値が大きい方の足が戻り中で、左右差から両足の余裕を引いても1°以上あり、入射側の機体ピークが8.5°以下である。

後者は、減速を確認してからでは遅れる可能性に対する先回りの仮説。将来の接地や減速を実測したものではない。8.5°は過大揺動中の追加を避ける試験上限で、歩行成功の基準ではない。

共通条件は、画像年齢160 ms以内、履歴一致度0.5以上、内部の不確かさ余裕が左右とも0.75°以下、前振れ量の余裕差引き後1°以上。機体の向心距離0.8°以上、足量で変える上限は最大5°、向心速度6〜45°/s、一定速度で見積もったZEROまでの時間が指令幅＋20 ms以上かつ250 ms以下。これらは未同定の試験条件であり、接地や必要仕事量の保証ではない。

通常ZEROの優先、1ピーク1早期試行、車輪・バッテリ・IMU・出力幅の保護を維持する。送信直前に判定経過5 ms以内・IMUサンプル年齢10 ms以内を再確認する。確実に送信しなかった場合は通常ZEROを残し、送信成否が曖昧なら重ねて出力せず停止する。

## 確認した範囲

3担当のサブエージェントが、予測器、入力設計、独立した因果再生を分担し、主担当が実装の統合・実機向けビルド・配信を確認した。

実C++予測器を使い、まだ届いていない将来フレームのカメラ値を採点専用として比較した。今回のrun 2 / run 3の平均絶対差は、新予測0.273° / 0.283°、直近値保持0.304° / 0.330°、旧直線外挿0.435° / 0.462°。7ログ中6ログで保持より平均差が減ったが、v9ログは小さく悪化した。独立した角度真値ではなく、大きな急変誤差も残る。

最初の保守的な通常入力移動案と、減速を待つだけのcoast案は、今回の2試行で候補が0だった。足の形状自身を用いる最終案では、記録された従来制御を因果更新したshadow上でrun 2に5候補、run 3に1候補。制御受け取りへ15 msの追加遅れを置くと4候補・1候補だった。これらは旧coast決定より67〜88 ms前の15 ms補助候補である。

過去の軌道上で条件を調べた結果であり、新出力後の運動や実機での出力実行を再現したものではない。実機の下流ガードで不採用になり得る。旧27908524の26.5秒頃の停止直前には候補がなく、その停止を防げることも未実証。
