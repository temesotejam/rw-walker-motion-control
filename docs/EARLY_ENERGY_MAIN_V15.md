# v15：必要エネルギーを満たす主入力の前倒し

2026-11-13。ユーザーの「前倒しでも不足を残さないようにできないか」「15ms上限に根拠がない」という指摘を受けた変更。環境 `atoms3cam-early-energy-main`、build ID `early-energy-main-v15`、実入力branch20、方策revision `walking_early_energy_main_v15`。v14/branch19は比較用に保持する。

## 変更の理由

v14の通常主入力は80msまで選べる一方、汎用前倒しは15msへ制限していた。この15msは限定的な短い試験入力から流用した値で、必要仕事・機体慣性・入力可能な時間から導いた値ではない。15msで不足が残っても、その半周期の主入力を置き換えてしまった。直近2試行では8度段階49/50件すべてがこの条件になった。

v15は前倒しを「通常の主入力を早く開始すること」として扱う。現在の姿勢・角速度・両側の過去ピーク・符号付き残留電流・電圧から、予測仕事が不足Jに届く幅を求める。幅だけを一律に増やす変更ではない。

## エネルギーによる選択と採用

U、速度による有効到達エネルギー、ピーク補正、Q/Wの係数はv14を変更しない。新しい最小整数幅の選択だけを別ヘッダ `walking_energy_policy_v15.h` に置く。

```
request = max(0, target_J + paired_peak_correction_J - available_J)
Q(T) = Ig*T + (I0-Ig)*tau*(1-exp(-T/tau))
W(T) = c1*omega*q(T) + c2*q(T)^2
T_required = min integer T such that W(T) >= request
```

Qの表示はmA·s、Wの式へ入れるqはA·s。正の不足に対して、最も近い仕事量へ丸める旧選択を、要求以上へ達する最短整数幅へ変更した。これにより1ms未満の丸めでも不足側を選ばない。要求ゼロの時だけ新規入力なしとする。

候補へ経過時間・車輪の保護を適用し、最終幅でQ/W/不足を再計算する。通常の主入力を置き換える前倒しは、**この保護後の予測仕事が要求を満たせる時だけ送信する**。満たせなければ送信前に見送り、通常ZERO待ちを復元する。送信済みのフラグを戻して二重入力する変更ではない。1e-9Jは数値/記録精度の丸めだけで、モデル誤差の許容幅ではない。

上限内で届かない通常ZEROは、その制約内の入力と未達Jを記録する。物理的に供給できる量を超えて「不足なし」と表示しない。低速の失速救済は通常前倒しと異なる条件の別試行として扱い、従来15ms上限を維持し不足を記録する。その15msも導出済みの物理限界とは呼ばない。

## 上限と時機の根拠の区別

汎用/足の前倒し主入力は、現在の通常主入力と同じ**80msの実験範囲**に統一した。80ms自体も力学から求めた限界ではなく、以前からの試行範囲である。Q表は100msまで、輸送関数の外枠は150msまでを受け付けるが、これらを根拠に自動で上限を広げない。

既存の `timingCap` は、過去の同側入力から対応ピークまでの時間から30msを引いた上限を用いる。過去の実測時間に基づく計画上の短縮であり、将来の反転時刻を保証しない。30msも従来の試験余裕である。

機構ゼロでは姿勢角の符号は変わるが、次のピークへ向かう角速度の向きは直ちに反転しない。したがって汎用前倒し主入力は、必要幅が推定ZEROまでの20〜30msを超えていても、機構ゼロをまたぐ予定にできる。ZERO通過だけを理由に打ち切らない。足姿勢を根拠とする別の前倒し経路には、従来の `width+25ms` 以上のZERO前余裕など厳しい条件が残る。すべての足条件を今回一律に緩めてはいない。

IMU/車輪/ピーク/足run・フレームの鮮度、時間上限、現在の電流指令上限、16度停止などは維持する。汎用を含むすべての任意前倒しは、計算前後で判断時刻から5ms以内、元IMUサンプルから10ms以内を確認する。

入力中の実際の反転を使う新しい打ち切り制御は実装していない。打ち切るなら実経過幅で終了電流・Q/W/pending予測を直し、ZERO前の反転で旧側へ戻る場合の状態遷移も扱う必要がある。今回は過去のtime-to-peak短縮と予定時間での終了を使用し、未実装の反転保護があるとは記録しない。

## 入力時計と記録

v15の通常/前倒し入力は、電流書込みの成功後をコマンド継続時間の起点とする。判断時刻へ時計を遡らせて、計算/通信にかかった時間の分だけ実際の入力期間を短縮しない。終了電流モデルの予定時刻も同じ起点へ合わせる。輸送中の正確な実電流ON時刻を測定した意味ではない。

判断時刻 `time_ms`、トリガー `zero_cross_time_ms`、実際のコマンド開始 `output_start_ms` / eventの `pulse_start_ms` を区別する。前倒しのトリガーを物理的なZERO通過時刻と呼ばない。

`walking_energy` には `early_budget_checked/admitted`、候補の仕事/未達、`output_q_pred_mas` / `output_work_pred_j` / `unmet_after_command_j` を保存する。見送った入力は候補を残し、出力側の予測Q/仕事を0、未達を要求全量として残す。これらはコマンドからの予測であり実測機械仕事ではない。
