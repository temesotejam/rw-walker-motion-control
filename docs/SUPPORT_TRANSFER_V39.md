# 次の支持足へ揺れを引き継ぐための入力予測

v39は±8°歩行中に、次の支持への移行を見越して「惰性で進む」「今から通電する」「少し待って通電する」を比較し、判断をRWLOGに記録する。実際のモータ電流はv19を基礎に決める。carry2で、実測に基づく左側への戻り補助の幅に以下の変更を加えた。[予測器](../src/support_transfer_plan.h) · [戻り補助の選択条件](ENERGY_ADMISSION_V19.md)

## v39-carry2の実通電と予測

左足が前に出たまま左右の揺れが止まった試行では、救済した後も機械的0°の手前で速度を失った。そこで、従来の減速判定が救済を選んだ瞬間に、受ける左足が低く、かつ足の前後差が短時間先まで残ると判断できる場合、必要な仕事の終点を左の足裏円弧の入口まで延ばす。追加分は実測した胴体の減速でその角度まで進む分と、同じ向きに5°/s残す分である。5°/sは今回の比較に使う仮の目標。実際に足にかかった荷重は測定していない。[実装](../src/receiving_arc_aid.h) · [実機での折り返し](../analysis/2026-11-20-carry1-trials/)

時間配分には、その測定の同じ向きですでに完了した主入力を使う。救済後の主入力があればその最大時間を、まだなければ他の同方向の主入力の最大時間を残す。どちらもまだなければ従来幅を使う。予約が制限するのは今回の延長分。従来の前後姿勢・回転速度・電流・半周期の上限とZEROでの切り替えが引き続き適用される。この段階で実際に変更する操作量は左向き救済の幅である。新たな開始時点と左右両方向の通電を選ぶ予測は、同期した実測と照合できるよう記録している。

救済を判断した左右の足姿勢と、戻り速度を得た画像の番号・撮影時刻をそろえる。同じ両足をすでに定周期で発行していればその値を使う。発行後に新しい両足の画像が届いていれば、受領後25 ms以内・撮影後75 ms以内で左右それぞれの速度が推定できたときだけ、その場で参照する。40 Hzの発行周期は維持する。両足が同じ画像にそろわないときには既存の救済幅を使う。判断理由、足角の取得経路、延長前の幅、候補幅、予約時間は `walking_energy.csv` の `arc_` 列で確認できる。[旧4走行での照合](../analysis/2026-11-20-carry1-trials/aid-replay.md)

予測を記録する際は、受け側の終端まで惰性で進めるという判断が同じ目標に2回続いても、通電停止直後は残留電流で加速し得ることを考慮する。RWLOGの `support_transfer_shadow` revision 3で、成功した電流ゼロ指令の後に実測された電流と経過時間を保持する。2枠を惰性として数えるには両方が電流の減衰条件を満たす必要がある。1枠ずつの予測余裕と候補の値も残す。これは実通電とは独立した評価である。

## v39-carry1で追加した到達判定

受ける足の最低点がすでに反対の足より低いとき、次に胴体がどこまで進めるかを調べる。受け足の横円弧は半径150 mmで、中心から横に5 mmのところに内縁がある。内縁を離れて円弧上を転がり始める胴体の左右角は、足の前後傾きに応じて変わる。前後傾きが0°なら、機械的0°を通過してから受け側へ約1.91°進んだところに相当する。これはCAD上の接点に関する条件で、荷重や滑りを直接測ったものではない。

予測器は、同じ半周期の連続する有効な足観測で高低の交代を挟めれば、その間の受け足姿勢から到達角を決める。最初の有効な観測ですでに受け足が低ければ、その姿勢を採用し、両者をログ上で区別する。決めた角度は同じ半周期内で固定する。その後の角速度と減速から終端に残るエネルギーを見積もり、電流の立ち上がりを含む通電候補と比較する。過ぎた切替の衝突損失は二重に差し引かない。

足の角速度と胴体の加速度を使うのは最長150 ms、または足角のモデル範囲に達するまで。その先に終端があるときは、局所予測の最後の両足姿勢を固定し、途中の重力による位置エネルギーの上昇と終端で受け側へ5°/sの速度を残す分を見積もる。実際に足が戻り続けるとこの見積もりはずれる。モデルが予測する円弧への到達、IMUで確認した速度、床に対する足の前進は別々に評価する。

RWLOGの `support_transfer_shadow` revision 2 は、`phase`（接近・受け側・到達）、`anchor`（交代を観測で挟めたか）、`terminal_deg`（終端の胴体角）、`terminal_ms`（現在の速度で進む場合の所要時間）を含む。切替後の `transfer_ms` は空欄。計算結果が使えた時刻はサンプルの取得時刻に `ready_after_us` を加えて求める。候補は記録専用で、モータに実際に流した電流は `walking_energy` と電流の実測系列で確認できる。

受け側の `coast_frames` は、同じ終端に惰性で到達できるという判定が何枠続いたかを0・1・2（2枠以上）で記録する。出力の許可条件を満たす隣接した足角枠を使い、間に通電が入ると数え直す。2回続いても実際の到達は未確定で、1回だけでも機体が進む場合がある。[直近2試行の通電と折返しの比較](../analysis/2026-11-20-webfix3-walking/receiving-replay.md)

revision 2の測定では、変換後に `python tools/score_observed_transfers.py <展開先> --terminal-out terminals.csv` を実行すると、終端でのIMU速度、演算が間に合ったか、途中の実通電の有無を1判断ずつ確認できる。

## 足裏の高低が切り替わる前の予測

1. 最新の左右足角とその変化率、胴体の左右角・符号付き角速度と加速度、前後角を使う。前振れプラスを両足のCAD角プラスに対応させている。カメラの絶対ゼロ・胴体の軸とCADの一致は仮定である。
2. 足が前へ出る、あるいは戻る動きと胴体の揺れを短区間だけ外挿し、左右の足裏の最低点が最初に同じ高さになる時点を探す。これは荷重移行の**幾何学的な目安**である。実機には荷重センサーがなく、足が床に触れた時刻、両足の荷重配分、滑りを個別には計測できない。[足裏とエネルギー中立点の関係](ENERGY_NEUTRAL_V14.md)
3. その位置を通過し、さらに**次の支持側へ1°進む**までを一つのホライズンとする。足は移行後も外挿した姿勢へ動く。予測できる範囲は現在から最大150 msとし、そこに終端が見つからなければ判定を保留する。「1°先で同じ方向に5°/s残る」は比較用に設けた暫定条件である。
4. 移行前は、観測した加減速が続くとしたときの到達運動エネルギーを見積もる。接触点が変わる瞬間に一部を失うモデルを使い、その後の重心高さの増加と、終端に残したい運動エネルギーを差し引く。衝突損失は、旧接触点回りに動く集中質量の速度を新しい接触点回りの接線へ射影して見積もる。この近似には脚・ホイールの個別の慣性、脚振りに伴う重心移動や滑りの実測値は入っていない。
5. 惰性で必要量が残れば通電幅はゼロとする。不足時は、通電開始を現在から25 ms刻み、幅を1 ms刻みで比較する。残留電流、電流の立ち上がり、実機由来の仕事モデルを使い、入力途中で先に停止する候補を除く。切替までに通電を終えられ、終端の条件を満たす最短幅を選ぶ。同じ幅なら次の観測まで待てる案を優先する。全候補が不足なら、不足が残ると記録する。モデル範囲内かどうかは別の列に残す。

候補ごとに別の歩行軌道を積分する代わりに、各判断では同じ局所予測の移行時刻を使い、次の足角発行で更新する。幅を変更したときの実際の接触時刻や受動脚の動きは実験で検証する対象である。CAD円弧の計算は、提供GLBに基づく従来の801点再構成と525姿勢で照合した。左右の足裏高低差の最大差は0.000025 mm未満。これは二つの計算法の数値的一致を表す。[CADの再構成](../tools/analyze_energy_neutral_v14.py)

足角はv38と同じ25 ms周期の推定器を使う。撮影時刻から推定時刻までの外挿は最大25 msで、有効と扱う画像年齢は最大75 ms。動く足の画像が50 ms前なら、残り25 ms分の位置のずれが移行時刻の予測にも影響し得る。左右それぞれの画像年齢を記録する。

## 過去の歩行2試行での結果

v37の実測2本（27・49半周期）を元のRWLOGからCRC照合して再生した。各判断ではその時点までに制御側が受け取った足画像と胴体・電流のデータを使う。後から取得した画像とIMUで足裏の高さを再計算して、符号が変わった区間を幾何上の切替の目安とした。両方に同じCADモデルを使うため、実荷重やCAD座標の正しさを独立に検証した値ではない。[半周期ごとの結果](../analysis/2026-11-20-support-transfer/half_cycles.csv) · [試行別集計](../analysis/2026-11-20-support-transfer/summary.json)

| 比較 | 結果 |
|---|---|
| 直ちに通電という候補 | 76半周期中5半周期、再評価を含む6判断。最初の候補は同じ半周期の従来の実入力より53〜174 ms早く、幅は12〜46 ms。6判断とも電流と速度から仕事を求めた同定範囲の外だった。 |
| 切替の予測時刻 | 後から得た足画像の切替区間より前に予測できた50件で、区間内の線形補間時刻との絶対差は中央値13.9 ms、最大80.2 ms。画像が切替を挟む間隔の中央値は約20 ms。 |
| 機械的ZEROとの順序 | 同じ半周期の機械的ZEROも確認できた51件のうち、切替を挟んだ画像区間が丸ごとZERO前にあったのが42件、ZEROをまたいだのが8件、丸ごとZERO後が1件。 |
| 惰性と予測の食い違い | 最初の予測から切替後1°まで新しいモータ指令がなく、同方向に5°/s以上残った36半周期のうち、最初の予測は「候補を使っても不足」18件、「通電待ち」3件、「惰性で十分」15件。 |

36件は到達を確認できた半周期に限った集計である。直前のパルスやホイール回転の影響は残り得る。末尾の2半周期は次ピークの前に記録が終了した。この2試行から、実際に停止する半周期の検出率や、候補の通電で転倒を防げる割合は求められない。v37ログからはv39の制御タスクの実行時刻とガード内部状態をすべて再現できず、再生した入力幅は当時の軌道上の比較値である。次の試行ではv39が実際に計算した `cap_ms`、`gate_mask`、`ready_after_us` も使う。

現時点では「早く出す」だけにすると、惰性で通過できる半周期にも余分な入力を加え得る。そこでv39では従来の実入力を記録しつつ、モデルが不足を見積もり過ぎる足姿勢・位相と、低速で実際に得られる仕事を調べる。

## 実機で残すデータ

いつもの[書き込みページ](../open-flasher.cmd)でv39を書き込み、バッテリーで行う通常の±8°測定でRWLOGを取得する。以下でログを展開できる。

```powershell
python tools/convert_rwlog_to_csv.py run.rwlog --out analysis/my-run
```

| 読む場所 | 確認する内容 |
|---|---|
| `support_transfer_shadow.csv` | 元のピーク、足角・速度・観測年齢、予測切替までの時間、惰性と候補の余裕（J）、候補の開始遅れ・幅を記録する。`capture_us32` は制御側が入力を取り出したマイクロ秒時計の下位32ビット、`ready_after_us` はそこから計算完了までの時間。`baseline_flags` は従来制御の出力とZEROの状態、判定番号はメタデータの `reason_names` に対応する。 |
| `metadata.json` の `support_transfer_shadow` | 記録対象件数、処理前の置き換え、保存・書き出し件数、最大計算時間と結果が届くまでの最大時間。空欄や欠落を惰性判定に数えない。 |
| `walking_energy.csv`、`timeseries.csv`、`foot_periodic.csv` | 実際の指令と電流、胴体が進んだ方向と速度、25 ms周期の推定値。周期抜けと取得できた足角の割合もv38と比較する。 |

### 映像や荷重計と照合する

実際の支持移行、反対足の振り出し、前進は別々に評価する。映像や荷重計を測定開始に同期し、切替を独立に判読できた区間を下表の列名でCSVに記入する。映像で接地・離地までしか識別できないときは、観測した事象を実験記録に明記する。映像のフレーム間や両脚支持で曖昧な区間は、その幅を残す。左右方向の符号は胴体の校正に合わせる。

| CSV列 | 値 |
|---|---|
| `start_ms`, `end_ms` | 移行が起きた最も早い時刻と最も遅い時刻。測定開始を0 msとする。 |
| `receiving_foot`, `body_direction` | 移行先の実際の足は左 `L`／右 `R`、その足へ向かう胴体の左右方向は `-1`／`1`。 |
| `opposite_foot_swung`, `forward_mm` | 次に反対足が振り出されたら1、観測できて振り出されなければ0。前進量は同じ一歩について床基準で測った距離（mm）。判断できない値は空欄。 |

```powershell
python tools/score_observed_transfers.py analysis/my-run labels.csv --out scored.csv
```

各移行につき、観測区間が始まる前に計算を完了した同じ半周期の最後の記録を照合する。評価するのは予測時刻の区間からのずれ、移行先の足と揺れ方向の一致、区間直後10 ms以内の新しいジャイロによる方向速度である。その最初の観測からさらに同方向に1°進んだ時点の角速度も記録する。観測が10 ms以上途切れた場合や途中の折返しは別に表示する。映像から判定した一歩と前進量も同じ行に保つ。予測が欠けた区間や左右が合わなかった区間も出力する。v39の試行で観測するのはv19の実入力下の結果であり、候補の電流を流したときの結果は別試行で測る。
