# 次の支持足へ揺れを引き継ぐための入力予測

v39は±8°歩行中に、胴体の速度と足の姿勢を使い、次の支持に揺れを引き継ぐための不足仕事を評価する。候補を比較する予測器の出力と、実際に指令した通電は区別してRWLOGに記録する。[予測器](../src/support_transfer_plan.h) · [戻り補助の選択条件](ENERGY_ADMISSION_V19.md)

## 通常歩行 walk7 の制御式と入出力

対象は測定画面の「歩行を開始（±8°・30秒）」、プロファイル `left_transfer_carry_v7`。対象ソースは [4e2b18e](https://github.com/temesotejam/rw-walker-motion-control/tree/4e2b18e68eda421bfd0a1aa32c640eb239d02559/src)。ここでは、一つの半周期で「惰行するか、いつ・どちら向きに・何 ms 通電するか」を変える計算と、その入力を作る観測式を扱う。関数の実装は [5つの歩行ソース](../src/README.md#walking-control) に、イベントを受けて実行する順序は [実行ループ](../src/experiment_runner.cpp) にある。

### 観測から制御に渡す量

計算を追う順序は [① 接地幾何](#walk7-geometry) → [② 惰行・接近予測](#walk7-coast) → [③ 通過と到達の実績](#walk7-transfer) → [④ 不足仕事](#walk7-demand) → [⑤ 電流・通電幅](#walk7-wheel)。どの式をいつ呼ぶかは[イベントごとの開始・終了条件](#walk7-timing)にまとめた。[比較専用の候補探索](#walk7-shadow)と[中立点・前進に関する未同定量](#walk7-neutral)も参照できる。

左右の足角を $\beta_L,\beta_R$（どちらも前振れが正）、胴体の左右傾きを $\theta$（機械的中心が0°、右が正）、前後傾きを $\phi$ と書く。角速度は胴体と脚で別の観測値。以下、電流の積分に使う時間は秒、指令の幅は整数 ms、モデル仕事は J。指数関数・三角関数・角速度の単位換算は各式に従う。

| 入力 | 求める量と使い道 |
| --- | --- |
| 左右それぞれの白マーカー位置 $x$ [px] | 各足の5点の校正表を区分線形補間する。区間内で $C(x)=a_i+(a_{i+1}-a_i)(x-x_i)/(x_{i+1}-x_i)$、足角は $\beta=C(x)-C(x_0)$。$x_0$ は静止した有効画像で得た平均位置。表の外は端区間の傾きで外挿し、制御への許容幅は校正端から5°。右はマーカーA、左はB。[足角の変換](../src/foot_angle_estimator.cpp)・[校正表とゼロ点](../src/foot_calibration.h) |
| 実測足角・撮影時刻・直近の変化 | 25 ms周期で送る足角は $\hat\beta=\beta_{\rm last}+v_\beta\min(\text{画像の経過秒},0.025)$。15～50 ms間隔の連続2区間で傾きの符号が一致し、両方とも絶対値80°/s以下なら、小さい方の絶対値とその符号を $v_\beta$ に採用。それ以外は傾きを0として保持し、画像の年齢が75 msを超えたら推定無効。実測角と推定角は別に保持する。[定周期の足角](../src/periodic_foot_state.h) |
| 前倒し主入力で使う左右の足姿勢 | 過去0.8～4秒の3画像の左右足角と直近3画像との差を6値の平均二乗誤差 $d$ で照合。上位2候補について重み $(1-d/0.5)/2$ で過去の角度変化（各±2°まで）を今の足角に加え、0・66・133・200 msの節点間を補間する。2候補の予測差と画像の年齢から左右の余裕角 $u_L,u_R$ を得る。条件を満たす履歴がない場合、直近3画像の戻りを使う局所推定もあり、補正は最大0.5°・25 ms相当。反転直後は条件を満たした実測値を保持する。前倒し判定にこの余裕角を渡す。[履歴照合・局所予測・採用条件](../src/foot_motion_prediction.h) |
| ジャイロ・加速度・バイアス | MEKFでは $q^- = \operatorname{normalize}(q\otimes\Delta q((\omega_g-b)\Delta t))$ で姿勢を予測し、正規化加速度と予測重力方向の残差で姿勢とバイアスを更新する。胴体左右角は更新後の $\theta=\arcsin(2(q_wq_y-q_zq_x))$ を度へ換算し、通常版では基準0°を引く。イベント検出の角速度は $\dot\theta=0.908911\,(g_y-b_y)$ [°/s]。ジャイロによる速度と姿勢角の有限差分は別物。[MEKF](../src/mekf6.cpp)・[角度とイベント検出](../src/experiment_runner.cpp#L4036) |
| 姿勢・前後の動き・左右の足の振れ | 前後角は開始時の基準に対する重力の前後成分と上向き成分から $\phi=\operatorname{atan2}(g_{\rm 前},g_{\rm 上})$ を求める。これは接地幾何と前後転倒の監視に使う。旋回補正用には、各足で外れ値に強い前振れ（2番目の最大値）と振れ幅（2番目の最大値−2番目の最小値）を求め、左右差と独立したジャイロ方位の1周期・2周期の変化を照合する。前進距離や床基準の絶対方位はこの計算の観測量に含まれない。[前後姿勢](../src/walking/wheel_input.h)・[足の左右差](../src/gait_turn_observer.h)・[ジャイロ方位](../src/control_trials/gyro_steering.h) |

### ① 足角と胴体姿勢から接地位置を求める

ここで $\theta$ は右向きを正にした胴体の左右角、$\phi$ は胴体の前後角、$\beta_L,\beta_R$ は各脚の胴体に対する前振れ角、$s=+1/-1$ は次に向かう右／左。実装の入出力は度・度毎秒で、三角関数の中ではラジアンに変換する。以下では $k=\pi/180$ とする。

| 式 | 入力 → 出力と使い方 |
|---|---|
| 足裏円弧の最低点 | 各足の絶対ピッチ $a=k(\beta_i+\phi)$、$S=\sin(k\theta), C=\cos(k\theta)$。円弧上で最も低い点の左右座標は $u=\operatorname{clip}(150 S/\sqrt{S^2+C^2\cos^2 a},u_{\min},u_{\max})$ mm。範囲は左足が $[-45,-5]$、右足が $[5,45]$ mm。前後方向には $\sin a\ge0$ なら $y=-28$、それ以外なら $+27$ mmの縁を使う。 |
| 左右それぞれの接地点と高さ差 | $x=c_i+u,\quad z=y\sin a+\cos a(67.09089-\sqrt{150^2-u^2})$。$c_L=-1.002092,c_R=0.997904$ mm。床に対する座標は $X=Cx+Sz,\ Z=-Sx+Cz$。高さ差 $G=Z_L-Z_R$ は負なら左足裏が低い。$G=0$ は両足裏が同じ高さになる幾何条件。左右の荷重割合、衝撃力、滑りはここでは測れない。 |
| 受け側の足裏円弧へ入る胴体角 | $\theta_e=s\,\operatorname{atan2}(5\cos a,\sqrt{150^2-5^2})/k$。受ける足の前振れと胴体の前後角から、円弧の接点が内側の縁を離れる角度を求める。足裏が水平なら約 $\pm1.91^\circ$。足裏高さが揃う場所・胴体の0°・円弧入口はそれぞれ異なる条件。 |
| 名目ピーク角 → 位置エネルギー | $m=0.1997$ kg、$g=9.80665$ m/s²、重心高 $h=0.120$ m、円弧半径 $R=0.150$ m、内側端 $x_i=0.005$ m、$c=\sqrt{R^2-x_i^2}$。$a=k\lvert\theta\rvert$、$a_i=\arcsin(x_i/R)$。$a\le a_i$ では $U=mg[x_i\sin a-2h\sin^2(a/2)]$、それより外側は $U=mg[(R-c)+2(c-h)\sin^2(a/2)]$。外側端 $\arcsin(0.045/R)$ まで。実通電のピーク目標・観測ピークに使う左右共通の基準で、足姿勢ごとの重心高や位置エネルギー最小点はこの式では動かない。 |
| 位置エネルギー → 到達角の大きさ | $y=E/(mg)$。境界 $U(a_i)$ 以下では $a=2\arctan\{y/[x_i+\sqrt{x_i^2-(2h+y)y}]\}$。それより上は $a=2\arcsin\sqrt{[y-(R-c)]/[2(c-h)]}$。予測エネルギーから $a/k$ 度を得る。領域外は無効。 |

実装は `detail::contact`、`detail::pose`、`supportGap`、`arcEntryDeg`、`lateral_energy::potential`、`lateral_energy::angle`。[接地幾何と名目エネルギー](../src/walking/contact_geometry.h)

### ② 胴体が止まる場所と、足裏が近づく時刻を求める

以下の $v$ は目標の支持側へ向かう胴体の角速度の大きさ（度/s）、$d>0$ はその向きの減速度（度/s²）、$\ell$ は進むべき角距離（度）、時刻 $t$ は秒。一定減速度は局所予測の仮定で、脚と床の力を逆算してはいない。

| 式 | 入力 → 出力と使い方 |
|---|---|
| 接近方向の速度・減速 | 直前のピーク側を $s_p$ として $v=-s_p\dot\theta$、中心まで $\ell_0=s_p\theta$。戻り補助の基本判定は新しいIMU標本を20 ms以上離して $d=(v_{\rm old}-v_{\rm now})/\Delta t$。左への円弧判定は足観測の更新に合わせてサンプリングした胴体角速度の差分 $(\dot\theta_n-\dot\theta_{n-1})/\Delta t$ を使う（15–50 msの差分を許容）。別の前倒し判定では、3標本中央値と過去100 msの最大値との差が4度/s以上の状態が3標本以上・10 ms以上続いたかも確認する。 |
| 停止距離・停止時間・残る速度 | $\ell_{\rm stop}=v^2/(2d)$、$t_{\rm stop}=v/d$、$v_{\rm end}^2=v^2-2d\ell$。残したい速度を $v_*$ とすると、$v^2\ge2d\ell+v_*^2$ なら惰行で届くという判定。左の円弧では $\ell=\theta-\theta_e$、基準 $v_*=5$ 度/s。基本の戻り補助は中心までの不足が1°を超えるか確認。新しい足画像で左右差が3°以上なら減速40度/s²以上、マーカー欠落なら60度/s²以上の減速の持続など、異なる発動条件を使う。 |
| 左への接近時刻を実測姿勢の変化から出す | 左足裏がまだ高く、連続する観測で $G_{\rm prev}>G_{\rm now}$ なら $t_{\rm eq}=\max(0,G_{\rm now})\,\Delta t/(G_{\rm prev}-G_{\rm now})$。足角差が正かつ3°未満で、減速と停止予測などの条件を満たす区間で使う。$t_{\rm eq}\le\min(\tau_{\rm rise},0.050)$ かつ $t_{\rm eq}<t_{\rm stop}$ なら、電流が立ち上がる間に足裏高さが揃うと予測する。すでに $G<0$ が続く場合には、連続した観測から受け側が低くなったことを確認する経路もある。 |
| 足が動き続ける場合の左足裏の高さ | 足角差が3°以上の枝では、実測角と推定角の両方で左右関係を確かめる。受け側がすでに低ければ $H=\min(0.150,\theta/v)$ の範囲で $\beta_i(t)=\hat \beta_i+\dot\beta_i t,\ \theta(t)=\theta-vt$ とし、$-G(t)>0$ の持続を検査する。足角変化で失いうる高さの上限は $28k(\lvert\dot\beta_L\rvert+\lvert\dot\beta_R\rvert)\Delta t$ mm。全区間または分割した各区間で判定する。 |
| まだ左足裏が高い場合の別の接近予測 | すでに選択済みの補助を延ばす判断で使う。$H=\min(0.150,t_{\rm stop},T_{\rm 既存通電}+\tau_{\rm rise})$。$\theta(t)=\theta-vt+\tfrac12dt^2$、脚は等角速度。時刻 $0,H/2,H$ の高さ差が単調に減り負に達すれば、0を挟む2点で線形補間して到達時刻を求める。実測足角・推定足角・胴体の前後回転を含む推定の3通りのうち最も遅い時刻を採用し、$t_{\rm stop}$ より前か確認する。 |
| 通電後に勢いが残ったか | 左向き補助の後で再び減速したとき、隣接する2つの減速の小さい方で停止距離・必要仕事、大きい方で停止までの時間を計算する。運動の減少量 $K_L(v_{\max}^2-v^2)$ と最初の補助のモデル仕事を照合し、継続補助では中心までの不足と25 msに進める角度 $0.025v$ も比較する。$K_L$ は後述の負側の速度二乗係数を度/s用に換算した値。 |

実装は `Tracker::update`、`Observer::observe`、`observeSmallArc`、`PostAidObserver`、`canCoastToArc`、`receiving_arc_aid::evaluate`、`return_crossing_work::closingTime` と `applyApproach`。[惰行と補助前後の状態判定](../src/walking/coast_motion.h) · [円弧の持続判定](../src/walking/required_work.h) · [動く足の接近時刻](../src/walking/wheel_input.h)

### ③ 左右の移行・到達に使う速度と実測回帰

| 適用先 | 入力 → 出力 |
|---|---|
| 左への通過履歴 | 中心を通過した時点の**主入力前の速度の大きさ**、その後1.5秒以内の左ピーク、対応した主入力を結びつける。平らな足の円弧入口（約1.91°）まで振れた記録を残す。実装には同じ目標での基準1件と、速度・目標エネルギー・主入力のモデル仕事と時間を組にした直近3件がある。今回を決めるときは4秒以内の完了した履歴等を選ぶ。後者は今回以下の目標の履歴も使用する。 |
| 左へ入れる補助から、次の中心通過速度を逆算 | $K_L=0.0002164565952\,k^2\approx6.59\times10^{-8}$ J/(度/s)² は左の惰行回帰係数。中心に届くだけの仕事を $W_0=K_L(2d\theta-v^2)$、実際に選べた補助幅のモデル仕事を $W_a$ とすると、条件を満たす枝で $\hat v_0=\sqrt{(W_a-W_0)/K_L}$。通過直後の主入力には、参考にした過去のモデル仕事に目標エネルギー増加分と参照速度に対する不足分を加えて時間を残す。実際に中心を通過した時点で主入力を再計算する。 |
| 右への通常の中心通過 → 次ピークの到達エネルギー | $\omega=k v$（rad/s）、$Q$ は通電中の予測電流積分（mA·s）。$E_R=0.000152963884+0.000465018868\,\omega^2+0.0000934855564\,\omega Q$ J。$v=21,36,40,47,51$ 度/sで許容する $Q_{\max}=12.4,11,8.5,3.3,0$ mA·sを線形補間。適用条件には補助なしの右向き実ZEROと当該コードの起動目標4.5°または5°がある。予測が目標を超えたときは $Q_*=[U_{\rm target}-E_R(v,0)]/(0.0000934855564\omega)$ を求め、元の幅以下の隣接する整数ms候補と惰行から誤差の小さい幅を選ぶ。 |

左の通過履歴は「どれくらいの速度で胴体中心を通ると、その後に左円弧へ届いたか」、右の回帰は「所定の速度・入力で右の次ピークまでどれだけ届くか」を表す。実機の荷重移行直前・直後における速度の対応 $v^+=f(v^-,\beta_L,\beta_R,\dot\beta_L,\dot\beta_R,\ldots)$ は左右とも未同定。参照した半周期の円弧到達だけでは、一歩の前進は確定しない。[`Reference::observe`、`MainPassages::observe`、`right_arrival_energy::predictedJ`](../src/walking/transfer_speed.h) · [`applyPassage` と `planPostAidPassage`](../src/walking/wheel_input.h) · [右到達回帰の呼び出し条件](../src/experiment_runner.cpp#L9157)

### ④ 不足する仕事を求める

以下は通常の ±8° 設定。$s=+1$ は右へ、$s=-1$ は左へ向かう胴体の半周期、$r=\lvert \dot\theta\rvert$ は度/s、$k=\pi/180$、$\omega=kr$ はrad/s、$[x]_+=\max(0,x)$。$U(\theta)$ は①の名目形状による位置エネルギー[J]、$T=U(\theta_*)$ はその時点の目標ピークのエネルギー[J]。目標 $\theta_*$ は開始時4.5°で、観測条件を満たす左右の組が続くごとに0.5°ずつ最大8°まで上がる。[目標の更新](../src/control_trials/tilt_priority.h#L208) · [実際に使う目標と姿勢](../src/experiment_runner.cpp#L8877)

| 計算 | 入力 → 出力と適用条件 |
|---|---|
| 惰行時の到達エネルギー | 現在の胴体角・角速度 → $P_0=U(\theta)+c_s\omega^2+b_s\min(1,r/20)^2$。後二項は無通電時の次ピークから推定した回帰と低速補間。実際の慣性モーメントや足裏での損失を直接測った量ではない。[回帰係数](../src/walking/coast_motion.h#L24) · [到達計算](../src/walking/required_work.h#L46) |
| 全体の振幅と左右差 | 反対側の直前ピークの $P=U(\theta_{\rm prev})$、同じ側の前回ピークの $S=U(\theta_{\rm same})$ → 平均 $M=(S+P)/2$、偏り $D=(P-S)/2$。補正 $C=\mathrm{clip}(0.25(T-M))+\mathrm{clip}(0.125D)$。それぞれのclipは $\pm0.125T$。同じ側の新鮮なピークがなければ $C=0$。同時に左右足が蓄えたエネルギーを測っているわけではない。[補正式](../src/walking/required_work.h#L78) |
| 同じ側で繰り返す到達誤差 | 対応の取れた無補助主入力の予測と実測ピーク → 誤差 $e=\mathrm{clip}(U(\theta_{\rm actual})-P_{\rm predicted}+B_{\rm applied},\ \pm0.5T)$。初回は $B=e$、その後 $B\leftarrow0.75B+0.25e$。2標本以上で最終観測から3秒以内の側だけ使い、使用時は $\pm0.25T$ に制限。[誤差の学習](../src/walking/required_work.h#L134) · [半周期の対応付け](../src/experiment_runner.cpp#L3442) |
| 主入力の不足仕事 | $P_{\rm avail}=[P_0+B]_+$、$W_{\rm req}=[T+C+\Delta_{\rm turn}-P_{\rm avail}]_+$。一般関数には追加仕事枠もあるがこの呼び出しでは0。$W_{\rm req}=0$ が惰行候補。通常ZEROでは直前の補助の効果を観測した角度・速度から改めて算出する。[要求とクリップ](../src/walking/required_work.h#L121) · [呼び出し](../src/experiment_runner.cpp#L8883) |
| 戻り補助の不足仕事 | 残り角距離 $\ell$[度]、実測減速度 $d$[度/s²]、現在速度 $r$、終点で残したい速度 $r_e$ → $W_{\rm loc}=c_s k^2(2d\ell+r_e^2-r^2)$。機械的中心まで止まらず届けばよい場合は $r_e=0$、左足裏円弧へ進む条件では通常 $r_e=5$ 度/s、同条件の通過履歴が使える場合はその実測速度を使う。惰行到達予測・ピーク補正を局所仕事へ加算しない。入力上限は基本 $0.5T$、認識欠落時の条件や小さい足角差からの円弧判定では $0.25T$。[局所仕事](../src/walking/required_work.h#L161) · [中心まで](../src/walking/coast_motion.h#L770) · [円弧まで](../src/walking/coast_motion.h#L867) · [補助の専用計算](../src/walking/wheel_input.h#L737) |

### いつ入力するかを決める式と条件

ここで $p$ は直前の胴体ピークの符号（±1）、$\theta$ はZERO検出に使う胴体の左右角、$\dot\theta$ はその向きのジャイロ角速度。中心に戻るときの距離は $D=p\theta$ [度]、速さは $v=-p\dot\theta$ [度/s] で、どちらも正になる。左右の足角 $\beta_L,\beta_R$ は前振れが正。実装では、主入力をその半周期に一度だけ選ぶ経路と、ZEROを残して先に補助する経路がある。

| イベント | 用いる量・式 → 得られる判断 |
|---|---|
| 起動と目標の段階変更 | ±8°の通常開始時は設定300 mA・100 msのキックを1回、指定方向に送る。初回ピークを観測してから半周期制御に入る。主入力の目標は4.5°から始まり、有効な左右ピークが対になり、目標を1.5°超えて行き過ぎることなく2組続けば `min(8°, 現目標+0.5°)` に進む。[開始処理](../src/experiment_runner.cpp#L2918)・[目標の更新](../src/control_trials/tilt_priority.h#L183) |

### 機械的な中心、エネルギーの中立点、実際の前進

機械的な中心は $\theta=0$、足裏高さが等しい姿勢は $G=0$。足姿勢を仮に固定したときのエネルギー的な中立角は $\theta_E=\arg\min_\theta U(\theta;\beta_L,\beta_R,\phi)$ という別の量で、滑らかな区間の重力トルクは $-\partial U/\partial\theta$。現行の主入力でピーク角を仕事に換算する際は①の名目位置エネルギーを使う。足の荷重割合・滑り・衝突による実損失、両方向の荷重移行直後の速度、実仕事 $\int\tau_{\rm 胴体}\dot\theta\,dt$ は実測で確定していない。[中立点の定義とCADの仮定](ENERGY_NEUTRAL_V14.md)

歩行速度 $\Delta s/\Delta t$ には床に対する変位 $\Delta s$ が必要。左右の足振れ・ジャイロ方位は左右差や曲がりの手掛かりになるが、歩行速度や床基準の進行方向を求めて目標に追従させる閉ループは未実装。

### 数値で見る二つの判断

足の前振れの下限が2°、左右差の下限が1°なら、前倒し主入力を許す胴体角の外縁は $1+1.2\times2+0.3\times1=3.7°$。これは、まだ中心まで3.7°ある段階から候補を評価できるという意味である。送信には残り時間、方向別の仕事モデルの適用範囲、電流・回転数の条件も必要になる。

別の例として、胴体が左へ戻っており、中心まで3.5°、内向き速度20°/s、減速度100°/s²とする。そのまま進める角度は $20^2/(2\times100)=2.0°$。中心の1.5°手前で止まる予測になる。左の係数で中心に届くための局所不足は $K_L(2\times100\times3.5-20^2)=19.78$ µJ。これは中心で残したい速度を0とした計算例で、受け側円弧へ勢いを残す補助では終点と要求速度を変える。両例の数値はPCで実装と照合した。機体で実際に必要な仕事はこの例からは決まらない。

## walk7 の戻り補助と中心通過後の通電

左へ戻る最初の補助が終わると、25 ms周期の足姿勢と胴体の減速で、中心を越えて次の足裏円弧へ届くかを再評価する。walk7では、ゼロ電流指令後にも駆動方向の実測電流が残っているとき、その観測の古さと指令までの5 msを見込んで残流を減衰させる。電流の一次遅れモデルから、ゼロ電流から1時定数だけ通電したときの電流に達する時間を求め、予測した折り返しまでに間に合うかを判定する。再通電の仕事は、同じ時間だけ惰性で進んだ場合との差で評価する。幅は折り返しまでの時間から指令遅延を引いた値、ホイール制限、半周期の残り通電枠で制限する。

過去4秒に、今回以下の目標エネルギーで実際に中心を越え、左足裏の円弧の入口まで揺れた半周期があれば、その中心速度と主入力のモデル仕事を参照する。現在の補助でその速度に届き、中心通過後の主入力に必要な時間も残せるときに、通過前後の配分を選ぶ。両方を満たせないときは中心手前の不足を優先する。中心通過時の実際の通電幅は、その時点の角速度と電流から再計算する。通常の歩行モードは1つで、設定は `left_transfer_carry_v7`。

RWLOGの補助行には判定で見込んだ応答時間 `arc_post_response_window_ms` を記録する。通過前後の配分を変更した行では、参照した中心通過時刻、補助の元の幅と選び直した幅、主入力に見込んだ残り時間が `arc_crossing_ref_zero_ms`、`arc_crossing_base_ms`、`arc_crossing_selected_ms`、`arc_passage_reserve_ms` で確認できる。歩行継続の検証には中心通過後の胴体角、左右の足の交互の振り、床基準の前進を用いる。

## v39-walk5の実測と通信修正

ここで検証したビルドは `walking-support-transfer-v39-walk5-logfix4`。歩行方式は `left_transfer_carry_v5`。logfix1から、通常の左補助と継続用の追加補助を同じ測定でRWLOGに記録できる。walk5のコンパクト表 `walking_energy.arc_aids` では、全行が一つの列名一覧を共有する。追加補助中の早期解除に使う減速度 `arc_post_release_decel_dps2` を全行に用意し、該当しない行にはJSONの `null` を記録する。数値を持つ行はそのままCSVに変換され、該当しない行は空欄になる。

## 同じ機体で前回の左戻り補正を比較する

## v39-turn1の通常ZERO入力

ホイールの反作用トルクで胴体が左右に揺れ、次の支持側へ荷重が移ると、反対の受動脚が振り出される。過去5走行では、胴体が負側へZEROを通過した83半周期すべてで右足、正側の70半周期すべてで左足の前振れ増加が相手足より大きかった。この位相関係を使い、±8°歩行で一方の足が出にくくなったとき、次の通常ZEROに要求する仕事を調整する。[実測と通電幅の照合](https://github.com/temesotejam/rw-walker-motion-control/tree/481a221e22352d8744a6accf8d1ce4670b6e9bcc/analysis/2026-11-20-turn-detection)

胴体が正のピークから負のピークを経て再び正のピークに達するまでを一周期とする。同じ画像から得た両足角を使い、前振れ角の差が2°以上、前後の振れ幅の差が1.5°以上で、同じ側の不足が二周期続くことを求める。さらに相対ジャイロ方位が二周期で3°以上変わり、各周期で逆方向への1.5°以上の変化がなければ確定する。半周期ごとに新しい両足画像が5枚以上あり、観測間隔と端の空きが125 ms以内であることも確認する。

実走で観測した「右足小・方位負」に対して、右足が振り出される負側の必要仕事を増やす。正側の直前の同側ピークが目標に届き、元の仕事要求も満たせるときは、左足が振り出される正側の仕事を減らせる。目標の変化量には一周期の左右の振れ幅差を用い、目標ピークを0.20°動かす仕事と、既存の回転数制限後の幅を10%（最大5 ms）変える仕事の小さい方を上限とする。これらは最初の実験のための設定値。通電幅は現在の揺動速度・初期電流・電流立ち上がりを使って逆算し、実測モデルの速度・電荷範囲、既存の通電枠と回転数制限を確認する。前倒し入力、救済入力、救済の入った半周期は元の支持移行の入力を使う。[仕事の計算](../src/walking/required_work.h) · [モータ指令への適用](../src/experiment_runner.cpp)

足の前進と床上の経路は動画で確認する。次の走行では、RWLOGの `gait_turn.csv` で左右の前振れ・振れ幅・相対方位を、`walking_energy.csv` で対応する周期の元幅・候補幅・実行の成否・実通電時間を照合できる。両者の対応には `turn_cycle_end_ms` を使う。

## v39-carry2の実通電と予測

以下の戻り補助はturn1でも使う。旋回を検出したときに通常ZEROで使う別の補正は[turn1の条件と実測比較](#v39-turn1の通常zero入力)に記す。

左足が前に出たまま左右の揺れが止まった試行では、救済した後も機械的0°の手前で速度を失った。そこで、従来の減速判定が救済を選んだ瞬間に、受ける左足が低く、かつ足の前後差が短時間先まで残ると判断できる場合、必要な仕事の終点を左の足裏円弧の入口まで延ばす。追加分は実測した胴体の減速でその角度まで進む分と、同じ向きに5°/s残す分である。5°/sは今回の比較に使う仮の目標。実際に足にかかった荷重は測定していない。[実装](../src/walking/required_work.h) · [実機での折り返し](https://github.com/temesotejam/rw-walker-motion-control/tree/481a221e22352d8744a6accf8d1ce4670b6e9bcc/analysis/2026-11-20-carry1-trials)

時間配分には、その測定の同じ向きですでに完了した主入力を使う。救済後の主入力があればその最大時間を、まだなければ他の同方向の主入力の最大時間を残す。どちらもまだなければ従来幅を使う。予約が制限するのは今回の延長分。従来の前後姿勢・回転速度・電流・半周期の上限とZEROでの切り替えが引き続き適用される。この段階で実際に変更する操作量は左向き救済の幅である。新たな開始時点と左右両方向の通電を選ぶ予測は、同期した実測と照合できるよう記録している。

救済を判断した左右の足姿勢と、戻り速度を得た画像の番号・撮影時刻をそろえる。同じ両足をすでに定周期で発行していればその値を使う。発行後に新しい両足の画像が届いていれば、受領後25 ms以内・撮影後75 ms以内で左右それぞれの速度が推定できたときだけ、その場で参照する。40 Hzの発行周期は維持する。両足が同じ画像にそろわないときには既存の救済幅を使う。判断理由、足角の取得経路、延長前の幅、候補幅、予約時間は `walking_energy.csv` の `arc_` 列で確認できる。[旧4走行での照合](https://github.com/temesotejam/rw-walker-motion-control/blob/481a221e22352d8744a6accf8d1ce4670b6e9bcc/analysis/2026-11-20-carry1-trials/aid-replay.md)

予測を記録する際は、受け側の終端まで惰性で進めるという判断が同じ目標に2回続いても、通電停止直後は残留電流で加速し得ることを考慮する。RWLOGの `support_transfer_shadow` revision 3で、成功した電流ゼロ指令の後に実測された電流と経過時間を保持する。2枠を惰性として数えるには両方が電流の減衰条件を満たす必要がある。1枠ずつの予測余裕と候補の値も残す。これは実通電とは独立した評価である。

## v39-carry1で追加した到達判定

受ける足の最低点がすでに反対の足より低いとき、次に胴体がどこまで進めるかを調べる。受け足の横円弧は半径150 mmで、中心から横に5 mmのところに内縁がある。内縁を離れて円弧上を転がり始める胴体の左右角は、足の前後傾きに応じて変わる。前後傾きが0°なら、機械的0°を通過してから受け側へ約1.91°進んだところに相当する。これはCAD上の接点に関する条件で、荷重や滑りを直接測ったものではない。

予測器は、同じ半周期の連続する有効な足観測で高低の交代を挟めれば、その間の受け足姿勢から到達角を決める。最初の有効な観測ですでに受け足が低ければ、その姿勢を採用し、両者をログ上で区別する。決めた角度は同じ半周期内で固定する。その後の角速度と減速から終端に残るエネルギーを見積もり、電流の立ち上がりを含む通電候補と比較する。過ぎた切替の衝突損失は二重に差し引かない。

足の角速度と胴体の加速度を使うのは最長150 ms、または足角のモデル範囲に達するまで。その先に終端があるときは、局所予測の最後の両足姿勢を固定し、途中の重力による位置エネルギーの上昇と終端で受け側へ5°/sの速度を残す分を見積もる。実際に足が戻り続けるとこの見積もりはずれる。モデルが予測する円弧への到達、IMUで確認した速度、床に対する足の前進は別々に評価する。

RWLOGの `support_transfer_shadow` revision 2 は、`phase`（接近・受け側・到達）、`anchor`（交代を観測で挟めたか）、`terminal_deg`（終端の胴体角）、`terminal_ms`（現在の速度で進む場合の所要時間）を含む。切替後の `transfer_ms` は空欄。計算結果が使えた時刻はサンプルの取得時刻に `ready_after_us` を加えて求める。候補は記録専用で、モータに実際に流した電流は `walking_energy` と電流の実測系列で確認できる。

受け側の `coast_frames` は、同じ終端に惰性で到達できるという判定が何枠続いたかを0・1・2（2枠以上）で記録する。出力の許可条件を満たす隣接した足角枠を使い、間に通電が入ると数え直す。2回続いても実際の到達は未確定で、1回だけでも機体が進む場合がある。[直近2試行の通電と折返しの比較](https://github.com/temesotejam/rw-walker-motion-control/blob/481a221e22352d8744a6accf8d1ce4670b6e9bcc/analysis/2026-11-20-webfix3-walking/receiving-replay.md)

revision 2の測定では、変換後に `python analysis/support/score_observed_transfers.py <展開先> --terminal-out terminals.csv` を実行すると、終端でのIMU速度、演算が間に合ったか、途中の実通電の有無を1判断ずつ確認できる。

## 足裏の高低が切り替わる前の予測

1. 最新の左右足角とその変化率、胴体の左右角・符号付き角速度と加速度、前後角を使う。前振れプラスを両足のCAD角プラスに対応させている。カメラの絶対ゼロ・胴体の軸とCADの一致は仮定である。
2. 足が前へ出る、あるいは戻る動きと胴体の揺れを短区間だけ外挿し、左右の足裏の最低点が最初に同じ高さになる時点を探す。これは荷重移行の**幾何学的な目安**である。実機には荷重センサーがなく、足が床に触れた時刻、両足の荷重配分、滑りを個別には計測できない。[足裏とエネルギー中立点の関係](ENERGY_NEUTRAL_V14.md)
3. その位置を通過し、さらに**次の支持側へ1°進む**までを一つのホライズンとする。足は移行後も外挿した姿勢へ動く。予測できる範囲は現在から最大150 msとし、そこに終端が見つからなければ判定を保留する。「1°先で同じ方向に5°/s残る」は比較用に設けた暫定条件である。
4. 移行前は、観測した加減速が続くとしたときの到達運動エネルギーを見積もる。接触点が変わる瞬間に一部を失うモデルを使い、その後の重心高さの増加と、終端に残したい運動エネルギーを差し引く。衝突損失は、旧接触点回りに動く集中質量の速度を新しい接触点回りの接線へ射影して見積もる。この近似には脚・ホイールの個別の慣性、脚振りに伴う重心移動や滑りの実測値は入っていない。
5. 惰性で必要量が残れば通電幅はゼロとする。不足時は、通電開始を現在から25 ms刻み、幅を1 ms刻みで比較する。残留電流、電流の立ち上がり、実機由来の仕事モデルを使い、入力途中で先に停止する候補を除く。切替までに通電を終えられ、終端の条件を満たす最短幅を選ぶ。同じ幅なら次の観測まで待てる案を優先する。全候補が不足なら、不足が残ると記録する。モデル範囲内かどうかは別の列に残す。

候補ごとに別の歩行軌道を積分する代わりに、各判断では同じ局所予測の移行時刻を使い、次の足角発行で更新する。幅を変更したときの実際の接触時刻や受動脚の動きは実験で検証する対象である。CAD円弧の計算は、提供GLBに基づく従来の801点再構成と525姿勢で照合した。左右の足裏高低差の最大差は0.000025 mm未満。これは二つの計算法の数値的一致を表す。[CADの再構成](../analysis/measurement/analyze_energy_neutral_v14.py)

足角はv38と同じ25 ms周期の推定器を使う。撮影時刻から推定時刻までの外挿は最大25 msで、有効と扱う画像年齢は最大75 ms。動く足の画像が50 ms前なら、残り25 ms分の位置のずれが移行時刻の予測にも影響し得る。左右それぞれの画像年齢を記録する。

## 過去の歩行2試行での結果

36件は到達を確認できた半周期に限った集計である。直前のパルスやホイール回転の影響は残り得る。末尾の2半周期は次ピークの前に記録が終了した。この2試行から、実際に停止する半周期の検出率や、候補の通電で転倒を防げる割合は求められない。v37ログからはv39の制御タスクの実行時刻とガード内部状態をすべて再現できず、再生した入力幅は当時の軌道上の比較値である。次の試行ではv39が実際に計算した `cap_ms`、`gate_mask`、`ready_after_us` も使う。

現時点では「早く出す」だけにすると、惰性で通過できる半周期にも余分な入力を加え得る。そこでv39では従来の実入力を記録しつつ、モデルが不足を見積もり過ぎる足姿勢・位相と、低速で実際に得られる仕事を調べる。

### 映像や荷重計と照合する

実際の支持移行、反対足の振り出し、前進は別々に評価する。映像や荷重計を測定開始に同期し、切替を独立に判読できた区間を下表の列名でCSVに記入する。映像で接地・離地までしか識別できないときは、観測した事象を実験記録に明記する。映像のフレーム間や両脚支持で曖昧な区間は、その幅を残す。左右方向の符号は胴体の校正に合わせる。

|---|---|

```powershell
python analysis/support/score_observed_transfers.py analysis/local/my-run labels.csv --out analysis/local/scored.csv
```

各移行につき、観測区間が始まる前に計算を完了した同じ半周期の最後の記録を照合する。評価するのは予測時刻の区間からのずれ、移行先の足と揺れ方向の一致、区間直後10 ms以内の新しいジャイロによる方向速度である。その最初の観測からさらに同方向に1°進んだ時点の角速度も記録する。観測が10 ms以上途切れた場合や途中の折返しは別に表示する。映像から判定した一歩と前進量も同じ行に保つ。予測が欠けた区間や左右が合わなかった区間も出力する。v39の試行で観測するのはv19の実入力下の結果であり、候補の電流を流したときの結果は別試行で測る。

## 形状変更後に検証する量（通常のwalk7）

重心高だけを変えて現行の `lateral_energy::potential()` を計算すると、機械的0°から8°までの名目位置エネルギーは120 mmで0.7334 mJ、128 mmで0.5810 mJとなる（約21%減）。これは同一円弧・同一質量での感度計算。テクスチャによる損失や実際の通電量はこの比較からは決まらない。

製作者によると2026年11月以降に機体形状の大幅な変更はなく、足裏にテクスチャを追加した。追加日、各試行の足裏状態、床との摩擦係数は未確定。まず、同じ床で足角・胴体の進入速度・実電流が近い半周期を左右別に比較し、支持移行直後の同方向速度、次ピーク、途中停止の件数を調べる。床基準の映像で荷重移行が識別できなければ、判読できた接地・離地・滑りを記す。
