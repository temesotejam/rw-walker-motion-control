# walk6の実測ログ再生

## walk7の戻り補助と中心通過後の通電配分

試行44453706と38871004の、最初の戻り補助が完了した28半周期を同じ過去の軌跡で比較した。walk7は2半周期で補助を早めた。残り26半周期の保存済み観測では開始時刻も幅も変わらなかった。

| 試行 | walk6での実測 | walk7が最初に変更する判断 | ホイール制限後の幅・通電枠の残り | 惰性を上回る追加仕事の予測／要求 |
|---|---|---|---|---|
| 44453706 | 18.211秒に最初の補助を終了。18.446秒に中心手前+0.89°で折り返した | 18.279秒、+2.45°、中心へ13.34°/s | 20 ms・残り29 ms | 16.31／162.63 µJ |
| 38871004 | 26.252秒に次の補助を決定し、26.255秒から40 ms通電。その後の再評価を経て、26.387秒の中心通過時に残り1 ms | 26.227秒、+2.41°、中心へ15.78°/s | 21 ms・残り28 ms | 15.97／82.61 µJ |

44453706では18.252秒と18.279秒の連続した観測で中心へ戻る速度が25.14°/sから13.34°/sに落ちた。後者の観測で電流は指令方向へ95 mA残っており、電流観測の経過時間は5.4 msだった。38871004では26.227秒に80 mA、経過時間14.3 msだった。いずれも電流ゼロから1時定数で達する水準（目標の約63%）までの時間を、残留電流を含めて評価できる。上表の仕事はこの短い入力で得られる追加分で、残る要求はそれぞれ146.3、66.6 µJ。残りの通電枠は指令幅どおりに通電を終えた時点の計算値で、次の中心通過時にその全量が残るかは実測が必要。

さらに33863489、34374950、41018458、33406765でも比較した。最初の戻り補助後24半周期のうち、変更した2半周期はどちらも33863489で、元の実走では中心を通過していた。

- 12.328秒では残り52 msのうち補助を37から35 msへ短縮し、中心通過後に17 msを残す。8.728秒の中心通過と、その後8.890秒に角度ピークが確認された入力実績を使った配分である。
- 15.202秒の26 msに相当する入力を15.104秒の16 msへ早める。変更後の入力で中心に到達できたかは新しい歩行データで判定する。

6試行を合わせ、2回目の補助が完了した17半周期の元の軌跡でも再評価を独立に実施し、3回目の補助の時刻・幅は変わらなかった。34374950の終盤の停止でも新しい機会は検出していない。

各半周期について、その時点までに機体が受信した足観測・IMU・電流・ホイール速度を使う。次の記録済み通電を決めたフレームまでを使い、変えた通電の後の軌跡や歩行距離を推定していない。直近2試行で実行された2回目の補助8件中、意思決定に使った姿勢・電流の同一フレームが保存されていた6件では旧判定の時刻が全件一致し、指令幅も5件で一致、1件で1 ms差だった。他の2件の欠けたフレームは補間していない。ホイール制限は、前回の通電と保存されたホイール速度から再構成し、各フレームに保存された上限と照合してから短い指令幅に適用する。

再現には下記の各行を実行する。2回目の補助後を比較するには、それぞれから `--after-first` を外す。

```powershell
$logs = '44453706','38871004','33863489','34374950','41018458','33406765' | ForEach-Object { "$env:USERPROFILE/Downloads/energy_control_autonomous_run_1_$_.rwlog" }
python -B analysis/2026-11-25-walk6-replay/replay.py --after-first $logs
python -B analysis/2026-11-25-walk6-replay/replay.py --after-first --event-allocation $logs
```

## walk6開発時の3試行

旧版で起きた動きと電流を使い、更新版が最初に追加の入力を選ぶ時刻を調べた。実機で次の支持へ移れたかは、新しい歩行測定で確かめる。下表の２つの判定は、同じ過去の運動に独立に適用した。19.753秒に新しい入力を加えた後の姿勢から23.228秒の再始動を予測したものではない。

| 試行 | ゼロ手前での再評価 | 元の軌跡が静止した後の最初の再始動候補 | 再始動のモデル仕事／要求 |
|---|---|---|---|
| 33863489 | 19.753秒、19 ms | 23.228秒、負方向47 ms | 21.45／20.33 µJ |
| 41018458 | 再評価を開始する2回目の補助なし | 19.483秒、負方向65 ms | 42.27／63.19 µJ |
| 33406765 | 同上 | 10.081秒、負方向62 ms | 31.05／107.65 µJ |

33863489では2回の補助が完了した半周期が9回あった。元の機体が次のゼロを越えた8回では保存されている観測に追加候補はなく、最後の半周期でだけ候補が出た。胴体角+3.13°、戻り速度10.20°/s。元の折り返しまで32 msあり、残り25 msに対してその時点のホイール制限は19 ms。予測不足130.85 µJに対し、19 msで惰性を上回る予測追加仕事は10.64 µJだった。

同じ試行の23.228秒では、胴体+4.80°、左足+2.22°、右足−0.13°だった。直近の負方向ゼロ通過時の速度は22.92、8.63、6.28°/s。各通過は反対側への振れを確認した後に採用し、3回の中央値8.63°/sから再始動の要求を決めた。最終通過の6.28°/sだけを使った比較では36 msだった。表の値は1回目の候補で、2回目の候補を元の軌跡上に生成していない。

## 再現手順

プロジェクトのルートで次のコマンドを実行する。PythonとC++17対応のg++を使用する。

```powershell
python -B analysis/2026-11-25-walk6-replay/replay.py "$env:USERPROFILE/Downloads/energy_control_autonomous_run_1_33863489.rwlog" "$env:USERPROFILE/Downloads/energy_control_autonomous_run_1_41018458.rwlog" "$env:USERPROFILE/Downloads/energy_control_autonomous_run_1_33406765.rwlog"
```

`replay.py` は一時フォルダーにRWLOGを展開し、ファームウェアの観測器とエネルギー計算を読み込んだ `detectors.cpp` へ観測値を渡す。展開済みのディレクトリも指定できる。

- 補助後の再評価には、足角の配信時刻、元画像の取得・制御受信時刻、同じ半周期に保存された姿勢・減速・電流・ホイール制限を使う。取得できなかった計算行は補間しない。時系列上のIMU値も照合し、途中でゼロに達した場合や外側へ折り返した場合の解除を反映する。幅は当時のホイール上限で評価した候補で、実機では通電直前にも確認する。
- 静止後の再始動は実測IMU時系列と、その時刻に制御へ配信済みの足角から判定する。前後傾は保存されたMEKF姿勢、測定開始時の前後傾基準、バイアス補正した角速度から復元する。前後傾ガード候補が発生したログは判定を保留する。モータ電流とホイール速度の観測時刻、電圧、元の通電区間も確認する。各制御周期の通信エラーレジスタや瞬間的な制御タスクの遅延はRWLOGから完全には復元できない。
- 3試行とも、最初の再始動候補が出るまでの通常揺動区間に再始動は出ていない。運動を変える新しい入力が選ばれた先の機体応答、床面への足の接触、歩行距離は再生結果に含めていない。
