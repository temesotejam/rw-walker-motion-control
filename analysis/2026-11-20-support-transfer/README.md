# 支持の切替を予測する制御の実測ログ再生

対象はv37で記録した2試行です。[再生ツール](../../tools/replay_support_transfer.py)は元のRWLOGのCRCを検査し、C++の[足角推定器](../../src/periodic_foot_state.h)と[支持移行予測器](../../src/support_transfer_plan.h)をPCで実行します。[half_cycles.csv](half_cycles.csv) は確認済みの各胴体ピークを起点にした76区間、[summary.json](summary.json) は試行別の集計と元ファイルのSHA-256です。

```powershell
python -B tools/replay_support_transfer.py "$env:USERPROFILE\Downloads\energy_control_autonomous_run_1_46492793.rwlog" "$env:USERPROFILE\Downloads\energy_control_autonomous_run_2_201405726.rwlog" --out analysis/2026-11-20-support-transfer
```

## 判断時点で使える情報

- カメラ観測は制御側での初回受信時刻に投入します。25 msの発行時点で片足ごとに外挿する上限は25 ms、元画像の許容年齢は75 msです。足速度は本体推定器が同じ観測列から得た値です。
- 胴体は発行時点までに記録された最新の制御側サンプルを使います。前後傾斜とそのガードは、試行開始時に定まった基準とログの姿勢・ジャイロから再構成します。前の胴体ピークは、記録された確認時刻から使用できます。
- 計算は次の支持側へ向かう運動を対象とし、機械的ZERO通過後も続きます。実行中の通電は除外し、同じ半周期ですでに完了した通電の実時間を80 msの予算から引きます。電流符号にはログの通常出力符号とドライバー極性の両方を適用します。電源電圧からモデル入力を6.18～8.02 Vに制限します。
- v37にはv39の発行・観測タスクが記録されていないため、発行時刻は25 msの等間隔を仮定します。丸められたIMU・電流・ピーク記録の時刻を使い、ホイール状態と到達時間による追加の幅制限は復元していません。実機の運動はすべて従来の制御で生じたものです。

## 実際の軌道との照合

予測とは別に、実際に撮影された左右の足角をその画像の撮影時刻に戻し、前後を10 ms以内のIMU測定で挟めた点でCADの左右足裏の高さを比較します。受け側へ符号が変わった連続2画像が50 ms以内にある場合に限り、幾何学的な支持切替の時刻範囲と補間値を求めます。半周期に複数回の切替が観測されれば、一意の時刻を割り当てません。実際の接地、床反力と滑りは測定されていません。

- `first_*` はその半周期で最初の該当判断です。各周期の `Drive` 回数と、そのうち仕事モデルの速度・電荷範囲内にある回数も保持します。`legacy_start_ms` は同じ起点ピーク・同じ揺動方向に対して従来版が実行した最初の入力です。
- `forecast_minus_proxy_ms` は、最初の予測時刻が切替の観測区間より前で、後から一意の切替を対応付けられたときの「予測した切替時刻 − 補間した切替時刻」です。`proxy_minus_mechanical_zero_ms` は実測の機械的ZEROとの時刻差です。
- 切替後に受け側の足裏が低い状態で胴体がさらに1°進んだときの方向付き角速度が `exit_direction_rate_dps` です。`coast_first_forecast_to_exit` はその予測から1°到達までの全通電区間（他の半周期を含む）と、10 ms以内の間隔で連続する実出力指令を照合します。直前の通電から電流が減衰している可能性はあります。`opposite_forward_excursion_deg` はその後の連続画像から求めた反対足の最大前振れ増分です。
- 時刻誤差・残留速度を照合できた区間には、観測可能な切替に到達したという選択条件があります。停止を正しく判別する能力、別の通電による改善、世界座標での一歩と前進は、この結果から確定できません。
