# 最後の左補助を解除した後、ホイールから胴体に戻った仕事

`41749536` では、最後の左補助を解除して約15 msは、ホイールの回転の絶対値が引き続き増え、胴体を左へ動かす側に仕事をした。その後、胴体が左へ進む途中でホイールが減速し、折返し付近までの区間は逆向きの仕事が正味で現れた。ホイールの速度レジスタをそのまま使うと、後半の減速を見落とす。[測定と停止位置](run.md)

## 2種類の回転速度とドライバの電流

ドライバは5.689656秒に−1200 mA指令を受理し、5.714119秒に0 mAと出力無効の書き込みを完了した。受理間隔は24.463 ms。ホイールの累積位置レジスタ（0x90、単位0.01°）を5点の二次式で局所近似して得た回転速度と、速度レジスタ（0x60）の読み値を比較した。各値に最も近い読み出し時刻を使っている。

| 解除からのおよその時間 | 位置からの速度（rpm） | 速度レジスタ（rpm） |
|---|---:|---:|
| 解除直前 | −252（−1.2 ms） | −36（−4.2 ms） |
| 15 ms後 | −282 | −91 |
| 50 ms後 | −273 | −151 |
| 100 ms後 | −245 | −202 |
| 145 ms後 | −230 | −218 |

解除直前のドライバ電流読み値は−190 mA、解除13.6 ms後は−161 mA、55.6 ms後は−89 mA、135.6 ms後は−28 mA。起動キックを除く14回の通電すべてで、解除直後60 ms内の読み値は元の指令と同符号だった。読み出し回数・内部の応答特性が違うため、電流・速度レジスタの変化だけから反作用の符号を決めると、累積位置が示す後半の減速を取り逃がす。以後の仕事評価では実測の胴体角速度と累積位置を使う。[解除時の電流処理](../../src/roller485_manager.cpp) · [位置と胴体角速度の計算](../../web/wheel_work.js)

## 胴体への反作用の仕事

RWLOGに記録した暫定のホイール慣性モーメント0.000028 kg·m²、ホイール・胴体間の軸符号 −1 を使った。軸符号を反映したホイール相対角速度に胴体角速度を加えて絶対角速度を求め、各微小区間で `−J × 胴体平均角速度 × ホイール絶対角速度変化` を積算した。これには軸受などを介した反作用も含む。実際の床反力や全機体のエネルギー損失は計測していない。入力選択に用いる次の支持への到達仕事と、この軸まわりの仕事は異なる物理量である。

| 最後の左補助（累積位置5点近似） | 計算対象時間 | 胴体への仕事 |
|---|---:|---:|
| 実通電中 | 24.46 ms | +291.3 µJ |
| 解除から15.5 ms後まで | 15.5 ms | +32.9 µJ |
| 15.5 ms後から144.5 ms後まで | 129.0 ms | **−28.1 µJ** |
| 解除から144.5 ms後までの合計 | 144.5 ms | +4.8 µJ |

上表の各区間は全長を観測できた。位置9点近似でも後半の仕事は−22.1 µJ。9点では急加速中の近似残差が大きく、通電中と解除直後の値は欠測だった。位置の5点・9点近似は中心時刻より後の標本も使う事後解析で、制御でその瞬間までに得られる速度とは区別する。読み出し時刻はいずれもI²C処理の中点であり、ドライバ内部の取得時刻・フィルタ遅れは未同定。

同じ手順で、以前の停止例 `68907120` と `135284989` の最後の左補助を調べた。解除後の最初の約15 msはそれぞれ +27.6 と +25.0 µJ。その後約130 msで −40.3 と −40.7 µJ だった。一方、`195727101` の最後の右向き通電では後半に +68.7 µJ が残る。解除後の仕事の符号は、回転数が減るかどうかと、そのとき胴体がどちらに動いているかの組み合わせで決まる。[過去2走の指令と胴体運動](../2026-11-22-return-trial/README.md)

## 速度を保つ案との関係

速度保持はハードウェア上可能である。現在の歩行ドライバは毎回電流モードを設定し、0 mAでは出力を無効にする。今回の解除時点で直近の速度レジスタを目標として保持すると、約−250 rpmで回転中のホイールに約−36 rpmを指示するため、かえって制動が強まる可能性がある。実回転に近い目標で保持する場合も、解除直後の正仕事と、その後の逆向き仕事の双方を変える。測定した −28.1 µJ をそのまま速度保持の改善量に換算することはできない。[モータ制御実装](../../src/roller485_manager.cpp) · [M5Stackの速度・電流モード仕様](https://docs.m5stack.com/en/guide/unit_roller485/usage)

歩行中の速度保持を評価するなら、位置の過去標本だけで求めた速度から目標を作り、空転時にモード切替の遅延・電流上限・符号・定常誤差を測る必要がある。現在の機体が右約4°で折り返すことへの寄与は、ホイールの後半の逆仕事、支持移行に伴う損失、胴体を復元する力の合計で決まる。今回の歩行制御は、次の支持で必要な運動に対して、まだ胴体が左へ向かう間に入力時点と仕事を選び直す方式として評価する。

## 再現

リポジトリルートで、既存の仕事計算と同じ入力検査を使って実行する。欠測時間と観測できた時間が各出力に含まれる。電流・速度レジスタの詳細出力には標準コンバーターで展開した同じ走行を使う。

```powershell
node analysis/2026-11-22-walk2-trial/release_work.js "$env:USERPROFILE/Downloads/energy_control_autonomous_run_1_41749536.rwlog"
python -B analysis/2026-11-22-return-trial/pulse_release.py "$env:TEMP/walker_walk2_20261122/41749536"
```
