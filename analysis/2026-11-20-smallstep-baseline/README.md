# 小歩幅の基準条件で選ぶ通電の照合

11月13日に小さい歩幅で歩いたv14の2走と、11月20日に約6秒・7秒で自立停止したturn2の2走を対象にした。基準条件は、胴体角と角速度から機械的0°までの到達時間を推定し、20 msより先、30 ms以内であればv14のエネルギー式で最大15 msの主入力を検討する。前倒しを見送った場合には実際のZEROで通常の仕事計算を行う。当時の実機2走には足姿勢に基づく前倒し通電と失速救済通電は各0件だった。[v14当時の実測報告](https://github.com/temesotejam/rw-walker-motion-control/blob/ce7d01871b3b31cd5e061fc813d8166bb65d4e13/analysis/2026-11-13-walking/v14実機2試行_172594684_294107213.md)

**v14の2走では、実行した157件と通電しなかった19件で指令幅が一致した。** 条件に入ったときの0°までの推定時間はそれぞれ23.61〜29.84 msと23.92〜29.97 ms。全176件で仕事の逆算幅、回転数制限後の幅、およびログに記録した予測電荷・仕事も照合した。旧版のログでは当時の全制御周期の鮮度、前後転倒保護、書き込み成否を新しい機体と同じ方法で再現できない。現在の実機ではこれらの保護が働き、同じ指令が出ない場合がある。

**直近2走では、最後に止まる約5〜7秒より前に指令の選択が変わる。** 最初の候補での胴体角と左向き角速度はそれぞれ+0.466°・−17.75°/sと+0.503°・−17.07°/s。turn2は両方で前倒しを見送り、機械的ZEROの制御イベントを0.471秒に記録し、その後52／56 msの主入力を指令した。基準条件は先に15 msの主入力を選び、実行できればその半周期の主入力を完了と扱う。その後は機体の運動も変化するので、表の2件目以降はそれぞれの旧軌道上での個別比較。表から新しい軌道の通電数や歩行距離は求められない。[直近の床上前進と停止](../2026-11-20-turn2-trial/)

再生には各RWLOGを標準コンバーターで展開し、`python -B analysis/2026-11-20-smallstep-baseline/replay.py <展開先> ...` を実行する。制御が記録した判断時刻、直近ピークと同側ピーク、胴体角速度、機械的な0°からの胴体左右角、起動中の目標角、初期電流・電池条件による到達電流、回転数・既存の通電履歴から、実装のv14仕事関数と回転数制限、基準条件の採否関数を呼び出す。起動パルス、比較側で使わないturn2の救済3件、および2走目の仕事計算入力が保存されていない1件は集計から除いた。判断時刻はログにある時刻であり、保存されていないIMU周期から新しい発火時刻を推定していない。[再生スクリプト](replay.py) · [C++ホストアダプター](selector.cpp)

## 次の実走で開始条件を比べる

RWLOGを展開し、`python -B analysis/2026-11-20-smallstep-baseline/summarize_start.py <展開先> [別の展開先 ...]` を実行する。各走の条件名、開始直前250 msの記録姿勢の中央値、最初の胴体ピークとその後に左右角の符号が変わった標本の時刻範囲、開始後5秒の指令幅を表示する。前倒しで主入力が済んだ場合も、中心を通過した時刻をIMUの記録から独立に読める。角度は0.01°刻みで、ここでいう通過時刻は保存された標本の時刻である。

この方法で読んだv14の2走の初回中心通過は318〜323 ms、283〜285 msだった。直近turn2は470〜474 ms、472〜475 ms。新しい比較試験でも初期軌道が揃っているかを確認する。床に対する一歩の判定には、足裏の印と床格子の映像を使う。[集計コード](summarize_start.py)
