# 以前に左へ移れた2回の減速度を参照する試験

11月20日の先行8走と直近2走について、右ピークから左に戻る途中で実行された補助を、当時の判断時刻で再計算した。受け足の円弧を確認し、その時点までに制御側に届いた元画像と照合できた11件では、保存されていた仕事の逆算幅と、ホイール回転数・主入力の予約を考慮した指令幅が全件一致した。

| 元の試行 | 左補助の実行 | 円弧と画像を照合できた判断 | 過去2回の条件が一致 | 幅が変わる判断 |
|---|---:|---:|---:|---:|
| 先行8走 | 21 | 8 | 0 | 0 |
| turn3・33125639 | 3 | 3 | 1 | 1 |
| 小歩幅・216664125 | 0 | 0 | 0 | 0 |

先行8走のうち、初期4走11件は足裏円弧の照合結果を保存しておらず、その条件を評価できない。円弧を記録した残り4走の10件のうち、2件ではその左補助の円弧端が確定していなかった。過去との比較は、前2回とも実際に左補助を完了し、同じ出発ピークの左向き主入力を経て、記録した左ピークが各回の円弧端に届いている場合に限る。確認を終えたピークのあとで履歴を更新した。ピーク判断内部のIMU健全性フラグは記録がないため、再生では記録した指令対応と直前10 ms以内の新鮮なIMU標本を照合した。

| turn3・補助判断 | その時点の減速度 | 従来の指令幅 | 続く左ピーク | 左の円弧端 |
|---|---:|---:|---:|---:|
| 2.091秒 | 77.21°/s² | 28 ms | −3.08° | −1.90° |
| 3.843秒 | 129.92°/s² | 33 ms | −2.71° | −1.91° |
| 5.592秒 | 59.75°/s² | 19 ms | 中心手前の+1.34°で折り返し | −1.91° |

5.592秒には、胴体は+4.81°から左へ19.58°/sで戻っており、制御が得ていた画像の左足角は+3.67°、右足角は−0.10°、画像の経過時間は44 msだった。前2回の小さい方の減速度77.21°/s²を使うと、受け足の円弧端までの要求仕事は29.32 µJから44.79 µJとなる。逆算幅28 msをホイール保護で24 msに制限し、前2回の短い方の実通電時間28 msの範囲に収まる。合計80 msから指令24 msを引くと56 msあり、その時点の主入力の予約48 msを満たす。予測上の仕事は22.55 µJから34.99 µJに増え、補正後の要求に対して9.80 µJ不足する。モータの指令を受け付けてから終了までに実際に経過する時間、荷重、接触時の損失、床上変位は、この変更だけから求められない。

このときの19.58°/sは、左向きの仕事モデルを同定した速度下限35.74°/sを下回る。要求・供給仕事の差はこのモデルを外挿した推定値である。5.592秒は保存軌道上で**左補助の条件を切り替えた場合**の最初の差である。現在の通常版と新試験版には右の到達仕事補正もあり、旧turn3の実測とは1.705秒の右への入力判断から異なり得る。新試験で同じ5.592秒の姿勢が生じる保証はない。小歩幅試行では新しい判断の前提となる左補助に一度も入らなかった。

実機で比べるときは、同じ配布版の標準条件と「左への戻りを過去2回に基づいて補正する」条件を参照する。補正した場合は前2回の参照ピーク、元の幅、実際の指令時間と経過時間、次の左ZEROと左ピークをRWLOGで確認する。歩行の比較には開始から同じ時間窓の映像を使い、左右交互の一歩と床に対する両足中点の前進を数える。

各走を標準コンバーターで展開して走行IDをフォルダー名にし、次のコマンドで照合できる。出力の各行に各走の全比較対象と指令幅の最初の差を記す。C++17に対応する `g++` を用いる。

```text
python -B analysis/2026-11-22-walking-simulator/return_history_replay.py <10走を展開した親フォルダー>
```

新しい試験のRWLOGは、シミュレータの `--evaluate-run` で実際の選択を集計する。評価した左補助、2回の実績との一致、延長候補、実際に延長を指令した回数を表示する。最初に延長を指令した半周期は、通電が当初の幅を実時間でも越えたか、最初に機械的0°と円弧端に達した時刻、後続の主入力と左ピーク、同区間の左右足角の変化幅を出す。途中終了した場合は実行時間を記し、欠けたログで件数が確定しない場合は確認できた下限を記す。足角の変化幅から床上の歩幅・前進距離は換算していない。
